# 해시 정적 자산의 배포 정책

## 결정

이전 배포의 해시 파일은 새 배포에서 별도로 보존하지 않는다. Vite 빌드는 `dist/public`을 비우고 현재 버전의 산출물만 만들기 때문에, 이전 해시 파일의 정리 시점은 다음 빌드 시점이다. 새 배포에는 이 최신 산출물만 포함된다.

열려 있는 탭의 수명에는 상한이 없으므로, 짧은 보존 기간을 설정해도 오래된 페이지가 항상 살아남는다고 보장할 수 없다. 이를 보장하려면 배포와 독립된 공유 저장소에 이전 자산을 복사하고, 수명주기 및 배포 간 동시 접근을 관리해야 한다. 현재는 외부 자산 보관 체계가 없으므로 이를 도입하지 않는다.

## 교체 후 동작

오래된 HTML이 새 배포에서 사라진 해시 청크를 요청하면 정적 서버는 SPA HTML 대신 텍스트 404를 반환한다. 지연 로드 경계가 오류 안내와 사용자가 직접 누르는 새로고침을 제공한다. HTML 응답은 `no-cache`로 재검증을 요구하므로, 새로고침은 현재 버전의 HTML과 청크를 다시 불러온다. 자동 새로고침 반복은 하지 않는다.

`npm run test:route-recovery-browser`는 프로덕션 빌드 두 개를 만들고 실행 중인 정적 서버의 현재 빌드 디렉터리를 교체한다. 이전 HTML을 유지한 브라우저가 이전 청크를 요청해 404를 받는지, 오류 안내가 표시되고 사용자가 새로고침을 누른 뒤 최신 경로가 열리는지 확인한다. 이 검사는 실제 배포 서비스 자체가 아니라 배포 시의 정적 파일 교체를 로컬에서 재현한다.
