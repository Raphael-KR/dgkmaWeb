# ADR 0003: 공통 공개 수집과 DB 규칙 저장

- 상태: Accepted — 기존 사용자 확정 결정의 사후 기록
- 기록일: 2026-11-09. 원래 결정일을 새로 추정하지 않는다.
- 정본: [제품·개발 계획](../product/planning-proposal.md), [수집 실행 경계](../../replit.md#경조사-런타임과-수집-경계), [수집 규칙 테이블](../reference/database-schema.md#table_row-source_collection_rules)

## 배경

사이트별 API만 추가하면 미지원 부고·모바일 청첩장·개원 안내의 JavaScript 화면을 처리하기 어렵다. 과거의 제3자 JavaScript 실행 금지 제한을 조정하면서 Mac 스킬 경로에 의존하지 않는 웹서비스 런타임이 필요했다.

## 결정과 비교한 선택지

기존 정적·공개 API 경로에 HTML·초기 상태·연결 JavaScript 분석, Playwright의 실제 Fetch/XHR 관찰·렌더링과 필요한 OCR을 공통 엔진으로 연결한다. 정적 정보가 충분하면 후속 브라우저·OCR를 생략한다. 브라우저를 허용하되 앱 Secrets·DB·회원 세션을 전달하지 않는 별도 프로세스·컨텍스트에서 제한적으로 실행한다.

사이트별 전용 구현만으로 끝내는 방식 대신 요청 흐름 안에서 공개 API를 발견한다. 실제 해당 페이지의 정보를 제공하는 인증 없는 읽기 GET으로 확인한 규칙만 직접 재조회한다. 규칙 정본은 앱 서버가 관리하는 PostgreSQL JSONB이며 배포 인스턴스의 로컬 YAML 영구 저장을 사용하지 않는다. 필요한 작성·추출 코드는 프로젝트에 포함한다.

## 결과와 제약

부고·결혼·개원이 수집기·규칙 저장소를 공유하되 유형별 필드·성공 조건을 구분한다. 규칙은 도메인·패턴·ID 추출·응답 매핑·구조 조건·버전·성공 시각을 담고 원문·개인정보·쿠키·토큰을 담지 않는다. 규칙이 맞지 않으면 재탐색한다.

주소·DNS·리다이렉트·하위 요청 검사, 시간·크기·실행 제한과 로그인/CAPTCHA 우회 금지를 유지한다. Chromium sandbox와 프로세스 분리는 VM 수준 격리를 뜻하지 않는다. 필드별 근거·사용자 정정 우선 원칙을 유지하며 HTTP 200만으로 성공 판정하지 않는다.
