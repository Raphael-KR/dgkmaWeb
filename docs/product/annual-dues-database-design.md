# 연도별 권리회원 판정을 위한 DB 변경안

개발 DB에는 회비수입원장과 회원별 납부 배분을 반영했다. 아래 네 개 판정 테이블은 설계를 확정했으며 실제 DB 적용은 별도 단계다. 회계장부의 정본은 사무국에 둔다. 홈페이지에서 현재 적용하는 기준은 당해 연도 완료된 연회비 합계 5만 원이다. 자격 규칙은 [제품 정책](planning-proposal.md#회원-등급과-회비), 실제 DB 구조는 [스키마 기준서](../reference/database-schema.md)를 따른다.

## 지금 쓸 수 있는 자료

| 판정 자료 | 사용 방법과 한계 |
|---|---|
| 동문과 가입·탈퇴 | `users.id`가 시트의 고정 동문 UUID다. `graduation_date`는 원래 정밀도로 보존한다. `joined_at`은 실제 홈페이지 가입 확정 시각이다. `alumni_status`와 `membership_history`의 가입 확정·탈퇴원 접수·사망 기록을 함께 읽는다. 승인 취소를 탈퇴로 계산하지 않는다. 이력이 비어 있는 기존 동문의 과거 상태는 확인 근거가 있을 때만 복원한다. 사망 기록의 `at`을 실제 사망일로 쓰지 않는다. |
| 기존 납부 기록 | `payments`에는 회원, 금액, 연도, 유형, 상태, 생성 시각이 있다. `created_at`은 실제 입금일을 증명하지 않는다. 자유 텍스트 직책인 `users.alumni_position`도 과거 특정 날짜의 직책을 증명하지 않는다. [스키마 코드](../../server/db/schema/index.ts) · [현재 등급 조회](../../server/modules/dues/storage.ts) |
| 사무국 회비수입원장 | `회비수입`의 ‘회비납부통계’ 피벗(J2)은 전체 원장 검산의 기준이며, 2022~2026년 귀속연도·납부자별 합계와 건수를 제공한다. ‘회원별 연간 회비납부 내역’ 피벗(Q1)으로는 표시된 2024~2026년의 회원별 연간 금액을 추가 대조한다. 건별 이관이나 특정 날짜의 판정에 필요한 실제 입금일·귀속연도·회원별 분개는 피벗의 기초 자료 A:H에서 확인한다. 대표 입금과 회원별 분개는 한 번만 집계한다. 직책별 기준은 O열에서 확인한다. 납부 기록만으로 미납자의 직책이나 명예회원 여부를 확정할 수 없다. [회비수입 시트](https://docs.google.com/spreadsheets/d/1aStEZeCSHIUqS4W81umlW8B3pMCJpx-u5Oe_IHcD49k/edit?gid=379091912#gid=379091912) |
| 통합주소록 입금자 대조(2026년 11월 21일) | 통합주소록 3,461명 중 올해 한 번이라도 납부한 157명의 UUID가 확인됐다. 이 대조 결과는 원장의 회원별 납부를 연결할 때 재사용한다. |
| 사무국의 2026년도 권리회원 판정 명단(11월 21일) | [회원별 납부 상황](https://app.notion.com/p/41f2225d9c4d81ce9db5cf89346706b8)은 사무국이 11월 21일 확정한 223명의 명단이다. 완납 102명·일부 납부 28명·미납 93명이며, 월납의 완납은 11월분까지 충족한 경우다. 개발 이관에서 개인에게 귀속된 2026년도 회비 632건·6,565,000원과 성명불상 1건·2,000원을 구분해 원장 합계와 대조했다. |

### 최초 입회와 홈페이지 권리 판정

사무국이 확정한 223명 전원의 동문회 최초 입회일은 명부의 졸업일이다. 졸업일은 원래 정밀도로 보존하고, 확인되지 않은 날짜는 비워 둔다. 실제 홈페이지 가입 확정 시각은 `users.joined_at`에 별도로 기록한다. 명단 이관으로 홈페이지 가입 이력을 만들지 않는다.

11월 21일 대조에서 명단 등재는 그날 동문회에 입회해 있었다는 근거로만 사용한다. [판정 함수](../../server/modules/dues/annual-eligibility.ts)는 그날까지 입금된 2026년 귀속 회비와 해당 직책의 최소 월회비 11개월분 또는 연납 기준액을 비교한다. 사무국의 납부방식·개인 약정액·완납 표시는 대조 자료다. 두 기준 중 하나를 충족하면 자격을 인정한다. 올해 입금해도 전부 2025년 귀속이면 2026년 납부 누계는 0원이다. [회원관리 및 회계 규정 제8·10·12조](../../client/src/features/about/regulations.tsx) · [제품 정책](planning-proposal.md#회원-등급과-회비)

2027년 이후 신규 등재되어 **최초 입회임이 확인된 동문**은 홈페이지 최초 승인일을 입회일로 쓴다. 과거 명단에서 대조하지 못한 기존 동문과 구별한다. [회원 기간 함수](../../server/modules/dues/association-membership-period.ts)에 이 두 경우를 구분해 전달해야 한다.

## 원장과 판정 자료의 저장 구조

기존 `users.id`를 동문 식별자로, `payments`와 `dues_receipts`를 납부 근거로 사용한다. 회원에게 표시할 당일 등급은 서버에서 계산한다. 기존 회원 상태와 가입 이력에는 회비 등급을 쓰지 않는다.

| 대상 | 저장할 내용과 제약 |
|---|---|
| 기존 `payments` 확장 | 원장 입금 참조와 원거래 내 배분 식별자를 추가한다. 회원별 확정 배분 한 건이 납부 한 행이다. 귀속 회비연도와 배분액은 기존 `year`, `amount`를 쓴다. 같은 원거래·배분 식별자 조합은 유일해야 한다. 정정 시 사유·시각·전후 금액과 귀속 변경을 해당 배분 이력에 기록한다. 기존 일반 납부 API가 만든 행은 원장 근거를 대조해야 새 판정에 편입할 수 있다. |
| `dues_receipts` 원장 입금 | 변하지 않는 원거래 식별자(고유), 실제 입금일(한국 날짜), 은행 입금 총액과 그중 회비 몫, 미배분 입금의 귀속연도를 둔다. 원장에 안정적인 ID가 없는 거래는 사무국 대조 목록에서 한 번 식별자를 부여하고 재사용한다. 시트 행 번호나 이름·금액 일치만으로 거래를 합치지 않는다. 계좌번호·은행 적요·연락처·증빙 사본은 가져오지 않는다. |
| `dues_rates` 연도별 회비표 | 회비연도·기준 버전·직책 조합은 유일하다. 최소 월회비와 연납 기준을 원 단위로 기록하고 시행일과 근거 조항을 둔다. 한 시점에 같은 연도·직책에 적용되는 기준은 하나다. 기준이 바뀌면 새 버전을 만들고 기존 판정이 참조한 값은 보존한다. 다른 연도의 요율은 그해 자료로 확인한다. |
| `dues_member_roles` 직책·명예회원 | 동문 UUID에 직책 또는 명예회원 구분과 근거를 연결한다. 같은 동문·구분의 효력 기간은 중복할 수 없으며, 다른 직책의 겸직과 연임은 허용한다. 임기 자료가 있으면 시작일·종료일을 기록한다. 기준일 명단으로만 확인한 직책은 확인 기준일을 따로 남기고 취임일을 추정하지 않는다. 해당 회비연도에 판정일까지 맡은 직책 중 최고 기준을 1월부터 적용한다. 명예회장은 일반회원 요율을 쓰고, 명예회원은 별도로 구분한다. |
| `dues_source_reviews` 자료 확인 범위 | 회비연도·한국 기준일·자료 종류·대상 범위별로 원장, 배분, 직책·명예회원, 기준일 명단의 출처와 확인 결과를 기록한다. 모집단 전체인지 일부인지, 개별 동문 중 신원이나 판정 근거가 미확인인 경우가 있는지 구분한다. 같은 근거의 재조회는 중복 등록하지 않는다. 자료가 달라지면 판정에서 참조할 수 있게 새 검토 기록을 남긴다. 확인 범위 안에서만 직책 없음과 납부 0원을 확정한다. 성명불상 입금은 미배분으로 두며 다른 동문의 판정을 막지 않는다. |
| `dues_decisions` 확정 자격 | 동문 UUID·한국 기준일·구분(전환 기준일 또는 월말)·버전 조합은 유일하고, 같은 날짜·구분에서 유효한 확정은 한 건이다. 자격과 판정 사유, 적용한 회비표와 자료 검토 기록, 당시 개인 납부 누계를 연결한다. 유예의 근거가 되는 월말 확정은 같은 회원 기간에만 참조한다. 근거 미확정 건은 자료 검토에 남긴다. 확정 후 정정은 사유와 직전 판정을 참조하는 새 버전을 같은 트랜잭션에서 기록한다. |

### 입금 반영과 재입회

원장에 귀속연도가 비어 있는 대표 수입과 이어지는 개인별 분개가 함께 있으면, 입금 일시·분개 범위·실입금액을 확인한다. 입금 한 건에 해당 분개를 연결하고 귀속연도별 합산에는 분개만 쓴다. 명부와 대조되지 않은 납부와 원래 성명불상인 입금은 구분해 보고한다.

2025년까지 총회에 보고한 일반회계 결산은 사무국의 신원 확인까지 마친 자료다. 원장의 납부자 표기가 개인 귀속의 근거이며, 홈페이지 UUID 연결은 별개다. 연결 근거가 없으면 ‘결산 확정·계정 미연결’로 원장 귀속을 보존한다. 성명불상으로 결산한 거래도 추가 조사하지 않는다. 적용 범위는 실제 입금연도의 결산을 기준으로 하므로 2026년에 받은 전년도 회비는 2026년 입금으로 처리한다.

[일반회계 장부 작성 매뉴얼 제4절](https://app.notion.com/p/41e2225d9c4d8196a397de7ac2b60c4b)에 따라 혼합 입금의 은행 거래는 사무국 장부에 한 건으로 보존하고, 회비에는 회비로 분개한 금액만 집계한다. 사무국 대조표에서는 은행 입금 총액이 회비와 다른 용도 분개의 합계와 같은지 확인한다.

- **개인·단체 납부.** 단체 대납은 실제 입금 한 건에 여러 회원의 배분을 연결해 개발 DB에 보관한다. 사무국은 CLI에서 원장 거래와 귀속 동문·연도·금액을 미리 본다. 배분 합계가 해당 입금의 회비 몫과 일치할 때 입금과 배분 전체를 한 트랜잭션으로 확정한다. 원장 총액에는 실입금을 한 번만 반영하고, 회원 본인의 납부 내역과 자격 판정에는 해당 귀속연도에 본인에게 배분된 금액만 반영한다. 판정일 이후의 입금은 제외하며 같은 연도의 오래된 미충당 월부터 충당한다.
- **미확인·정정.** 1월 12일 성명불상 2,000원은 원장 합계에 남고 회원별 합계에서는 빠진다. 입금자가 확인되면 같은 원거래에 배분한다. 중복·오배분은 사유와 전후 배분을 추적해 정정하고 재실행 때 이중 합산을 막는다. 사무국 원장의 양수 입금 관행에 맞추며 정정용 가상 환불 거래를 만들지 않는다.
- **탈퇴와 재입회.** 탈퇴 즉시 홈페이지의 납부자 연결을 해제하는 현행 처리를 유지한다. 일상 원장 반영에서도 이 연결을 복구하지 않는다. 재입회 승인 시 사무국이 그해 원장을 동문 ID와 대조해 확인한 기존 배분 행에만 회원을 다시 연결한다. 새 입금이나 새 납부 행을 만들지 않는다. 대조 중 자격이 확정되지 않으면 ‘확인 필요’로 둔다. 탈퇴 기간은 권리에서 제외하며 재입회 전 회원 기간의 유예는 승계하지 않는다. 과거 자격·직책·배분 정정 이력으로 탈퇴자의 납부자를 재식별할 수 있는 연결도 [탈퇴 시 비공개·파기 기준](pre-migration-database-design.md#탈퇴)에 포함한다.

### 판정과 홈페이지 표시

- 전월 말 확정 자격은 같은 회원 기간의 다음 달 1~10일에 사용한다. 12월 31일 자격도 다음 해 1월 10일까지 이어지고, 전년도 납부액은 이월하지 않는다. 11일부터는 당해 연도 기준을 적용한다. 후일의 직책 변경이나 입금이 이미 확정된 월말 값을 덮어쓰지 않는다.
- 판정 함수에 필요한 자료가 비어 있으면 ‘확인 필요’ 사유를 보낸다. 확인된 납부 0원·일반회원과 구분한다. 서버 응답에서 **권리 여부·근거**, **실제 납부액·입금일**을 따로 제공해야 유예 중인 회원을 ‘연회비 완납’으로 잘못 표시하지 않는다.
- 홈·내 정보와 본인 납부 내역, 권리회원 단체방, 경조사 호칭은 같은 서버 판정을 사용한다. 단체방은 승인된 로그인 회원 본인의 권리가 확인될 때만 주소를 반환한다. 경조사 대상자의 자격과 작성자의 등록 권한은 각각 확인한다. 회원 UUID와 사무국 대조 근거는 회원 응답에 노출하지 않는다.

### 기존 홈페이지와 새 판정을 함께 대조하는 방법

- **납부 중복과 조기 등급 변경.** [현행 집계](../../server/modules/dues/storage.ts)는 완료된 연회비 행을 모두 합산한다. 비교 기간에는 홈페이지의 기존 납부와 원장에서 처음 가져온 배분을 생성 출처로 구분한다. 기존 조회는 전자만 읽고 새 판정은 원장 대조가 끝난 배분만 읽는다. 기존 납부와 정확히 일치하면 그 행에 원장 참조만 추가한다. 금액·귀속이 충돌하면 대조 대상으로 남겨 기존 홈페이지에 표시되는 금액을 바꾸지 않는다.
- **납부 API의 공개 범위.** [본인 납부 조회](../../server/modules/dues/routes.ts)는 현재 회원 ID만 제외한 행을 반환한다. 스키마 확장과 함께 회원용 조회 필드와 일반 관리자 납부 입력 필드를 각각 명시한다. 일반 납부 API를 통해 원장 배분을 확정할 수 없도록 하고, 내부 원거래 키·정정 이력은 회원 응답에서 제외한다.
- **탈퇴와 동시 입금 처리.** 원장 반영과 재입회 시 재연결에서도 [탈퇴 처리](../../server/modules/identity/storage.ts)와 같은 동문 행을 잠근 뒤 최신 회원 상태를 확인한다. 탈퇴 처리와 입금 반영 순서가 바뀌어도 납부자 연결은 해제된 상태로 남아야 한다. 단체 입금은 같은 원거래의 배분 변경과 전체 합계 확정을 한 트랜잭션에서 처리한다.

## 적용 순서와 승인 범위

개발 DB에 회비수입원장을 이관하고 관리자 집계를 대조했다. 피벗 대조 범위와 금액은 [개발 이관 기록](../history/dues-ledger-development-2026-11-21.md)에 있다. [11월 21일 개발 판정 대조](../history/annual-dues-comparison-2026-11-21.md)에 223명의 결과와 근거를 기록했다. 판정용 네 테이블의 실제 적용과 홈페이지 전환은 후속 단계다.

이관 대상은 계속 늘어나는 `회비수입` 원장 표의 전체 거래 행이다. 최초 반영 후 같은 표를 다시 읽어 이미 반영한 입금은 한 번만 유지하고 새 입금만 추가한다. 과거 거래가 달라지거나 사라지면 사무국에 차이를 보고하고 자동 삭제·덮어쓰기를 중단한다. 스프레드시트의 피벗 셀을 홈페이지에 복제하지 않는다. 관리자 전용 회비 화면은 DB에 반영한 입금과 배분을 집계해 귀속연도별 건수·금액과 회원별 연간 납부액을 표시한다.

1. **원장 이관 준비.** [검산 CLI와 개발 이관 절차](../runbooks/database-operations.md#개발-회비수입원장-이관)에 따라 시트를 읽어 검산한다. 2026-11-21 기준 두 피벗과 대조한 1,849행·36,538,000원 중 1,837행·36,514,000원을 개발 명부의 동문 228명과 연결했다. 이 합계에는 사무국이 납부자 기수를 정정한 2025년 4월 7일 입금 50,000원이 포함된다. 성명불상 12행·24,000원 중 11행은 2025년 결산 표기를 유지하고 2026년 1행은 기존 미배분 기준을 따른다. 혼합 입금 2건은 은행 총액 430,000원, 회비 120,000원, 다른 용도 310,000원으로 대조를 마쳤다. 이관 형식에서 은행 총액은 `bankAmount`, 회비 몫은 `amount`로 보존한다. 다른 용도 금액은 두 값의 차이로 계산한다.
2. **이관 결과를 검산한다.** 첫 이관 이후에도 새 입금을 반영할 때 같은 기준을 적용한다. 이관한 회비를 귀속연도·납부자별로 묶어 J2 피벗의 건수·금액과 대조하고, Q1에 표시된 연도는 회원별 연간 금액도 맞춘다. 단체 입금은 원입금과 개인별 분개를 중복 집계하지 않고 미배분액을 포함해 원장 총액을 맞춘다. 차이가 남으면 해당 거래와 사유를 기록한다.
3. **검산 후 2026년 권리회원 판정을 대조한다.** 사무국 명단 223명을 기존 `users.id`와 대조한다. 입금자 157명의 확인된 UUID를 재사용하고 [개발 명부에 추가된 대학원 3명](../history/users-roster-cutover-2026-11-21.md#회비-원장-대조-후-개발-명부-증분)도 같은 UUID를 사용한다. 회원별 자격 판정 결과를 사무국 명단과 비교하고, 신원 미확인과 자격 판정 차이를 구분한다.
4. 10일·11일과 연도 경계, 같은 해 재입회를 확인한다. 사무국이 자료의 확인 범위와 개발 대조 결과를 검토한 뒤 홈페이지 전환 시점을 정한다. 운영 DB 적용과 배포는 별도 승인으로 진행한다. 사무국 회계장부 전체 이전과 결제 연동은 별도 사업이다.
