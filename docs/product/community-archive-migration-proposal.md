# 다음카페·밴드 이관 기준

로컬 백업 자료를 dgkmaWeb으로 이관할 때 적용하는 분류·공개 범위·저장·변환·검증 기준이다. 수집은 [백업 운영 문서](../runbooks/community-backup.md), 원 게시판별 목적지는 [다음카페 이관 계획](daum-cafe-migration-plan.md)을 따른다.

## 이관 단위와 입력

다음카페 백업, 다음카페 마이그레이션, 밴드 백업, 밴드 마이그레이션은 네 개의 독립 작업이다. 각 작업의 대상·범위·진행 상태·완료 조건·실행 결과를 따로 관리하고 보고한다. 한 플랫폼의 승인·완료를 다른 플랫폼에 적용하거나, 백업 완료를 마이그레이션 시작으로 연결하지 않는다.

- 다음카페 `dkkmob` 마이그레이션: 확정된 전체 자료를 한 번에 반영하는 일회성 이관이다. 증분 비교·병합·재동기화 기능을 만들지 않는다. 대상 환경의 posts 전체 행(일반·경조사·발행·가림·초안 포함)과 종속 댓글은 실제 이관 직전에 리셋한다. 테이블·컬럼·카테고리·회원·명부·회비와 로컬 원본 백업은 삭제하지 않는다. 다음카페 백업만 입력으로 삼고 별도 실행 지시 후 처리한다.
- 밴드 `@dkom` 마이그레이션: 백업 데이터만 날짜 기준으로 증분 수집하며, 이관은 확정한 기준일까지의 전체 백업본을 한 번에 반영하는 일회성 작업이다. 밴드 운영 중에는 마지막으로 백업한 날까지의 자료를 먼저 분류해 개발 환경에 이관한다. 원본과 대상의 건수, 댓글·답글 관계, 첨부 열람, 다음카페 글·사진첩 보존을 검증하고 제외·미확보·실패 항목을 검토한 뒤 밴드 마지막 게시일과 홈페이지 전환일을 정한다. 마지막 게시일이 한국 시간으로 끝나면 최종 증분을 백업하고 개발 완료본을 대조한 뒤 운영에 한 번 이전한다. 개발 검증분이 최종본에 중복되지 않게 원본 ID를 대조한다.
- 원본과 이관 대응표는 로컬 SQLite에서 관리한다. Replit에 이관 전용 DB·테이블을 만들거나 SQLite·원본 백업을 업로드하지 않는다. 홈페이지에는 선택한 최종 자료·허용 첨부만 목적지별 기존 구조로 이관한다.
- 새 ‘이전 카페’ 게시판을 만들지 않는다. 기존 게시판에 분류한다.
- HWP 등 구형 첨부는 로컬 원본을 보존하고 허용 형식으로 변환한 뒤 이관한다. 이름만 바꾸거나 기존 업로드 보안 규칙을 완화하지 않는다.
- 원본 백업과 변환 결과·이관 상태는 구분한다. 원본 ID·게시판·작성자 표시·작성일·본문·댓글·첨부를 보존한다. 수집 작업에서 쓰는 로그인 비밀번호·쿠키·인증 토큰은 저장하지 않는다.

## 이관 대상 환경

백업→개발 이관과 개발→운영 이전을 분리한다. 백업 입력 도구는 개발 DB·개발 파일 저장소만 대상으로 한다. 개발에서 수정·완성한 이관 게시글(import_data가 있는 발행 글, 가림 상태 포함)과 연결 첨부, 전체 사진첩 카탈로그·사진을 묶어 내보내고 사용자가 승인한 릴리스에서 그 묶음을 운영에 반영한다. 정식 운영 개시 전에는 운영 이전분도 테스트 데이터로 취급한다. 운영은 원본 백업을 다시 읽거나 변환하지 않는다. 회원 계정·명부·회비·세션·일반 테스트 글·초안·홈페이지에서 작성한 댓글은 이 콘텐츠 이전에 포함하지 않는다. 밴드에서 이관한 댓글·답글과 원문 연결은 밴드 개발 완료본의 검증 대상이다. 이관 글의 author_id는 NULL이며 명부와 이름으로 연결하지 않는다.

게시글 ID·본문·작성자 표시·원작성일·출처·가림 상태·수정 버전은 개발 완료본대로 유지하고 카테고리는 이름으로 대응한다. 첨부의 앱 내부 경로와 앨범 ID도 유지하되 물리 파일은 운영 저장소에 복사·해시 확인한다. 공개 역사관 JSON·문서·사진은 Git 코드 릴리스로 함께 반영하고 DB 이전 도구로 복제하지 않는다. 원본 백업·SQLite·개발 내보내기 묶음은 비공개로 관리한다. 실제 내보내기·리셋·이전·배포는 별도 실행 지시에서 수행한다.

정식 전환일 전에 사용자가 운영 이전 시험을 지정하면 검증한 개발본을 운영 DB·비공개 저장소에 시험 반영하고 그 결과를 실행 기록에 남긴다. 게시판·사진첩 시험은 게시글과 종속 댓글을 비운 뒤 두 플랫폼의 전체 게시 자료를 채우고 사진첩 카탈로그를 교체한다. 시험 전후에 회원·명부·심사·로그인 상태의 보존을 확인한다. 운영 시작일과 운영 앱 배포는 각 실행 범위에서 별도로 정한다.

## 이관 후 공개 범위

이관 자료에는 **dgkmaWeb의 분류 체계와 목적지별 접근 정책**을 적용한다.

| 이관 목적지 | 적용할 열람 범위 |
|---|---|
| 커뮤니티 게시판의 각 카테고리 | 로그인한 승인 회원 전용 |
| 역사관 사진첩 목록·앨범 상세·사진 원본 | 로그인한 승인 회원 전용 |
| 동문회 소개·회칙과 사진첩 외 역사관 자료 | 현재 목적지 정책에 따라 비로그인 공개 |

본문·첨부·사진도 해당 목적지의 열람 범위를 따른다. 원본의 접근 등급은 출처 기록으로 보존하되, 그 등급만으로 추가 승인을 요청하거나 이관을 보류하지 않는다. 목적지의 회원 인증·관리 권한은 유지하며 로컬 원본 백업은 비공개로 보존한다.

## 저장 경계

`local-backups/community/archive.sqlite3`는 수집 목록·본문 원본 참조·파일 참조·내용 해시·원본/대상 ID 대응·변환/적용 상태를 관리하는 로컬 작업 DB다. 디렉터리 0700·파일 0600으로 제한하고 Git·Replit·클라우드 동기화에서 제외한다. 원문 JSON과 다운로드 파일은 같은 로컬 백업 트리에 유지한다. 캐시나 폐기 가능한 앱 테스트 데이터로 취급하지 않는다.

이관 입력은 다음카페 `local-backups/community/daum-dkkmob/`, 밴드 `local-backups/community/band-11089836/`로 구분한다. 공통 SQLite의 `source`·`container_id`로 원천을 식별하며 변환·이관 대응표와 결과 집계에서도 이 구분을 유지한다. 기존 백업·SQLite·실행 영수증을 이동하거나 삭제하지 않는다.

게시글 본문은 기존 `posts.content` Tiptap JSONB에 저장한다. `event_data`·`source_text`는 경조사 전용 의미를 유지한다. 원작성자를 현재 회원과 이름으로 자동 연결하거나 임의의 회원 계정을 만들지 않는다. 원작성자 이름·원작성일·출처 플랫폼·원본 ID·원 게시판·원문 주소는 본문과 분리한 posts 메타데이터로 이관한다. 화면의 작성자·날짜·출처 표시는 해당 DB 값으로 제공한다. 원본 ID/대상 ID의 적용 추적은 로컬 SQLite에도 유지한다. 이관 글의 `author_id`는 회원 계정에 연결하지 않고 NULL로 둔다. 원작성자 이름을 회원 계정 미연결 안내로 대체하지 않으며, 나중에 가입해도 과거 글의 수정·삭제 권한을 부여하지 않는다. 원작성자 이름은 posts.author_name에 저장한다. 다음카페의 등록 작성자가 ‘운영자’이고 제목 끝이 ` / 이름` 형식으로 명확한 경우, 끝의 이름을 author_name으로 옮기고 제목에서는 해당 접미부만 제거한다. 이름으로 회원 계정을 연결하지 않는다. 카페 등록 작성자와 원래 제목은 원본 백업에서 보존하며, 구분자·이름이 불명확한 제목은 임의로 분해하지 않는다. 원작성일·출처는 posts.import_data에 저장하며 [스키마 계약](../reference/database-schema.md#게시글-이관-출처-저장)을 따른다. 일반 작성 API의 회원 인증·작성자 부여, 수정·삭제·가리기 권한은 바꾸지 않는다.

다음카페 이관 게시글은 `import_data.platform=daum-cafe`를 기준으로 본문 바로 위에 한 칸 표처럼 테두리가 있는 공통 안내 박스를 표시한다. 문구는 “[다음카페:동국대학교한의과대학총동창회](https://cafe.daum.net/dkkmob)에서 이관되었습니다.”로 통일한다. 안내는 본문 JSON에 삽입하지 않으며 본문 검색·편집·학술 첫 문단에 섞이지 않는다. 기존 원문 링크와 게시판 출처 표시는 유지한다.

밴드 게시글과 댓글·답글의 기본 작성자 표시는 확인된 실명이다. 밴드 프로필 또는 가입 안내 댓글에서 작성자의 성명을 확인하고, 그 성명이 개발 기본명부에서 한 사람에게만 일치하면 졸업기수 없이도 명부 실명을 쓴다. 같은 성명이 여럿이면 확인된 졸업기수로 한 사람을 구분한다. 별칭만 있거나, 작성자 성명·댓글이 가리키는 계정이 충돌하거나, 명부에서 한 사람을 구분하지 못하면 사무국 확인을 기다린다. 원문의 표시명과 소속·직함 소개는 비공개 원본에 보존한다. 사무국이 재학생의 당시 직책까지 표시하도록 확인한 계정에는 `당시 {직책} {실명}`을 표시한다. 졸업기수나 졸업예정연도는 부여하지 않는다. 밴드 소개를 홈페이지 프로필에 반영할 때는 본인 확인을 거쳐 `users.affiliation`에 표시 문구 한 줄로 저장한다. 실명 사용은 현재 회원 계정이나 편집 권한을 연결하지 않는다. 실명을 확인할 수 없는 자료는 원본과 로컬 대응표에서 확인 대기로 남기며, 답글의 상위 댓글이 보류되면 해당 연결도 보류한다.

## 자료별 분류

사무국이 밴드 계정의 소유자까지 직접 확인한 경우에는 그 계정의 원글·댓글·답글에 확인된 실명을 쓴다. 교직원 등 기본명부 밖의 작성자도 같은 기준을 적용한다. 직접 확인한 원문과 계정의 대응은 로컬에서 검산한다. 특정 글만 확인한 경우는 그 글에 한정한다.

회원 계정과 연결되지 않는 밴드 글에는 확인한 실명과 당시 직함을 표시한다. 이후 홈페이지 프로필을 이관 글에 소급하지 않는다. 사무국이 반복되는 기수 표기를 해석해 준 경우 그 성명과 표기 조합에만 해당 졸업기수를 적용한다. 서로 다른 계정의 동명이인은 각각 확인한다.

밴드 표시명이 ‘(알 수 없음)’인 계정과 사무국이 스팸으로 특정한 계정의 자료는 백업에만 보존한다. 이름이 남아 있는 계정은 밴드의 내부 탈퇴 표시가 있어도 실명 대조를 계속한다. 스팸은 밴드 계정 키로 식별한다. 제외 계정의 원글에는 하위 댓글·답글을 포함하고, 다른 글에서 그 계정이 쓴 댓글은 해당 댓글과 답글만 제외한다. 작성자 정보가 누락된 것만으로 탈퇴자로 판정하지 않는다.

밴드 단일 피드의 일반 게시글은 구조화된 분류가 없는 경우에도 본문 전체의 `#태그`에서 목적지를 먼저 찾는다. 밴드 태그 표식과 일반 텍스트에 직접 쓴 해시태그를 모두 읽는다. URL 조각은 분류 태그에서 제외한다. 목적지가 여럿이면 검토 대상으로 남기고, 목적지 태그가 없을 때는 본문에서 부고·경사·공지·행사·소식임이 명확하면 해당 카테고리, 그 밖의 일반 글은 자유에 둔다. 분류만으로 경조사 사실정보를 만들어 넣지 않는다. 게시 목적지와 작성자 실명 확인은 독립적으로 판정한다. 사무국이 특정 원글의 작성자를 직접 확인하면 그 글의 원본 ID·해시에만 확인한 실명을 적용한다. 같은 계정의 다른 글이나 댓글까지 일괄 확정하지 않는다.

`#알림`·`#안내`·`#홍보`처럼 여러 게시판에 쓰인 태그는 본문과 백업된 첨부·링크 미리보기로 게시 목적을 확인한다. 행사 초청·신청은 행사, 개최 결과·동문 동정은 소식, 회원에게 적용되는 절차·기한은 공지로 분류한다. 결혼·개원 안내는 경사, 별세 안내는 부고, 개인 답례·영업 홍보·업무 참고자료는 자유에 둔다. 근거가 부족하면 확인 대기로 남긴다. 글별 결정은 원본 ID와 해시로 재사용하며 원문이 바뀌면 다시 검토한다. 본문에 외부 서비스 접속정보가 남아 있으면 사무국이 해당 안내의 게시 범위를 확인할 때까지 보류한다. 사무국이 확인한 행사 협찬 기록은 소식에 둔다. 이관 제외로 확정한 대화 캡처나 앨범 생성 안내는 해당 원글·댓글·답글을 함께 제외한다. 앨범 사진은 원래 앨범에 보존한다. 본문이나 사진에 개인별 연락처 명부·식별 가능한 진료 내용 등이 노출되면 목적지는 정하고 공개 여부를 따로 검토한다. 옛 서비스의 설정 변경·커버 변경 등은 정형 문구와 원본의 서비스 카드 또는 첨부를 대조하여 제외한다. 회원이 작성한 일정의 행사명·일시·설명은 일정 생성 알림 문구와 함께 확인해 행사나 결과 소식으로 분류한다.

밴드 신규 가입 알림, 회원이 쓴 가입 인사, 가입 환영 카드는 댓글·답글 및 첨부와 함께 로컬 백업에만 보존한다. 가입글에서 확인한 실명·졸업기수는 다른 글·댓글의 작성자를 대조하는 근거로 쓸 수 있다. 같은 계정이 올린 일반 글과 다른 글에 쓴 댓글은 독립적으로 판단한다. 가입을 언급하면서 실제 부고·행사 등 별도 소식을 전한 글은 그 내용으로 분류한다. 다른 자동글과 그 하위 댓글도 백업에 보존한다. 앨범 생성 안내와 원래 앨범의 사진은 따로 판단한다.

- 원 상위 메뉴·하위 게시판별로 목적지를 정한다. 원본 ID·원 분류·대상 메뉴/카테고리·공개 범위를 이관 대응표에 기록한다.
- 게시판 자료는 기존 게시판의 내용에 맞는 카테고리로 분류한다. 확인되지 않은 내용을 경조사 사실정보로 추정하지 않는다.
- 다음카페 동국임상연구회·학술 게시판 자료는 자유 게시판에 이관하고 본문 첫 문단에 `#학술`을 일반 텍스트로 한 번 넣는다. 학술 카테고리는 신설하지 않는다. 태그 텍스트는 Tiptap JSON에 보존해 향후 본문 검색 대상으로 사용하며, 원분류는 출처·로컬 대응표에 별도로 유지한다.
- 동창회앨범은 회원 전용 역사관 사진첩으로 이관한다. 게시글의 이미지 40개 제한을 적용하거나 앨범을 분할하지 않는다. 목록과 확보한 사진은 대상 환경의 비공개 Object Storage에 저장하며 [역사관 콘텐츠 기준](../reference/heritage-content.md)을 따른다.
- 역대임원 자료는 공개 역사관의 기존 항목과 대조·병합한다. 동일 대수·직책·성명은 합치고 사진을 재사용한다. 회장 재임 기간은 확정된 역대회장 명단을 우선한다.
- 다음카페 모교 연혁은 역사관 이관 대상으로 포함한다. 학교·한의대·부속병원 등의 모교 기록임을 표시하고 동문회 연혁과 구분해 연결한다.
- 과거 인사말·연혁·회칙은 해당 시기의 자료로 구분한다. 현행 소개·연혁·회칙을 자동으로 덮어쓰지 않는다.

밴드 일반 첨부는 개발·운영별 비공개 보관 위치에 저장한다. 해당 환경에서 이관한 밴드 글 또는 댓글이 참조하고 그 자료를 열람할 수 있는 회원에게만 제공한다. 회원의 일반 업로드·첨부 등록 경로와 분리한다.

밴드 사진의 목적지는 원문 내용과 행사 근거로 정한다. 동문회·기수 모임·모교의 행사를 기록한 사진과 동문회 역사자료는 회원 전용 역사관 앨범에 두고 원글에는 ‘사진첩 보기’ 링크 하나를 둔다. 개인 일상·감상·학술·안내 등 일반 글은 사진이 10장을 넘어도 사진 전체를 같은 원글에 첨부한다. 원문·댓글·별도 첨부는 보존한다. 피드와 색인의 사진은 원글 번호와 사진 ID로 대조하고 영상 표지는 제외한다. 회원의 일반 업로드 제한은 유지한다. 원글의 밴드 전용 스티커는 생략하고 작성자가 남긴 본문과 확인된 사진·첨부를 옮긴다.

원글에 붙은 일정은 확인된 제목·날짜·장소를 본문에 표시한다. 종일 일정은 날짜만, 시간이 지정된 일정은 한국 시간으로 표시한다. 참석자·응답 명단은 옮기지 않는다. 비공개·삭제 일정의 내용은 게시하지 않는다.

밴드 사진이 첨부 용량 상한을 넘으면 원본을 보존하고 JPEG의 무손실 압축을 먼저 시도한다. 사무국이 지정한 JPEG는 해상도를 유지한 고품질 사본이 상한 이내면 이관한다. 원본·이관 사본의 해시와 해상도를 대조한다.

밴드 댓글·답글에서 스티커 원본을 확보하지 못했으면 작성자가 남긴 텍스트를 그대로 옮긴다. 스티커만 있던 댓글·답글은 이관에서 제외한다. 다른 첨부가 함께 있으면 그 첨부의 검증 기준을 적용한다. 작성자 실명, 상위 글·댓글 연결과 원문의 열람 제한도 확인한다.

밴드에서 이관하는 댓글·답글에는 확인된 사진을 개수 제한 없이 원래 댓글에 원본 순서대로 첨부한다. 영상도 같은 댓글에서 회원 전용으로 재생한다. 사진이나 영상만 있는 댓글도 대상이다. 1,000자를 넘는 원문도 댓글 한 건으로 보존한다. 원본에 작성자 이름과 계정 식별자가 모두 없는 댓글과 그 하위 답글은 백업에 보존한다. 홈페이지에서 새로 작성하는 댓글은 본문 1,000자와 첨부 한 개를 받는다.

밴드에서 확보한 MP4는 이관 게시글 전용으로 제공한다. 같은 게시글의 회원 열람 권한과 가림 상태를 영상 스트리밍·탐색 요청에도 적용한다. 일반 회원의 영상 업로드 허용 형식은 기존 기준을 따른다.

## 본문·첨부 변환 기준

밴드 첨부가 만료됐거나 원본과 미리보기에서 모두 404를 반환하면 해당 파일만 생략하고 남아 있는 본문·사진·댓글을 보존한다. 진료 사례 기사는 개인을 식별할 수 있는 부분을 가려 게시한다. 행사·부고 공지의 연락처와 안내 내용은 회원 전용 게시판에 보존한다. 사무국이 개별 검토한 진료·거래·부고·기부 기록과 당시 회원에게 공유한 안내는 확정한 원글별 공개 범위를 따른다. 별도로 관리되는 인증 키와 세션·토큰은 이관 입력에서 제외한다. 참가신청서·설문을 포함한 글은 작성자의 안내문과 댓글을 옮긴다. 투표는 질문·선택지와 원본에서 확인되는 합계를 옮긴다. 응답자 식별 정보는 백업에 보존한다.

사무국이 원글별로 복사 금지 표시가 붙은 자료의 게시를 확정하면 백업에 남은 원문과 확보한 사진·댓글을 옮긴다. 실제 원문 열람 제한을 별도로 확인한다. 다운로드가 막혀 확보하지 못한 파일은 원본 ID·사유를 남기고 해당 글의 나머지 자료를 먼저 옮긴다. 스티커는 원글·댓글 모두 생략한다.

임원 연락망 사진은 로컬 백업으로 보존한다. 정정본에서 확정된 성명과 직책은 해당 대수의 역대 임원 자료에 반영한다. 게시할 본문 없이 공유 미리보기만 남은 원글과 사무국이 역사관에서 직접 정리하기로 한 문서 묶음은 백업에 보존한다.

공유가 허용된 외부 밴드 글과 페이지는 작성자가 쓴 본문과 원문 링크를 보존한다. 장소 카드는 글에 안내한 행사장의 이름과 주소로 표시한다. 원본 앨범이 연결된 역사관 자료는 마감일의 사진 색인과 원글 첨부를 대조한다. 같은 사진 묶음이 이미 역사관에 있으면 그 앨범으로 연결한다. 원문 링크에 접속정보로 오인될 수 있는 조회 매개변수가 있으면 해당 부분을 생략해도 원문 기사나 공개 게시판의 주소가 남는지 확인한다.

게시판으로 이관하는 글은 현재 설치·설정된 Tiptap 스키마의 문단·H1~H4·목록·인용·구분선·코드·표·기본 인라인 서식·링크·이미지로 정규화하고 원문 텍스트를 공백 차이 외 동일하게 보존했는지 대조한다. 굵게·기울임·밑줄·취소선은 HTML 태그뿐 아니라 동일 의미의 인라인 CSS도 해당 Tiptap mark로 변환한다. CSS 글꼴·크기로 제목 레벨을 추측하지 않고 H1~H4 태그를 기준으로 한다. 새 확장이나 임의 CSS·HTML 실행을 도입하지 않는다. 지원하지 않는 옛 글꼴·색상·상첨자 서식은 원문 백업에 남기고 이관 본문에는 텍스트를 보존한다. 원본 확보 실패 이미지는 누락 안내로 표시하고 변환 결과의 한계를 기록한다.

HWP 첨부의 자동 변환은 로컬 CLI `rhwp`를 사용한다. 사용자가 지정한 변환본은 우선 적용한다. 선택된 HWPX는 내부 내용·이미지 대조 없이 첨부하며 외부 PCX 참조 이미지 누락은 원래 문서의 특성으로 기록하고 보류하지 않는다. 원본·변환 경고·선택 기록은 보존한다. 기존 업로드 형식·용량·압축 파일 보안 검사는 유지한다. 에이전트가 한컴오피스나 외부 변환 웹사이트를 사용하지 않는다.

## 플랫폼별 이관 절차

1. 개발 완료 후 사용자가 지정한 플랫폼·대상 환경·실행 범위만 처리한다.
2. 그 플랫폼의 로컬 백업으로 게시판별 분류·원출처 표시·허용 첨부 변환을 준비하고 대상·보류·누락을 구분한다.
3. 확정한 적용 목록을 기존 저장 계약·[DB 운영 런북](../runbooks/database-operations.md)에 따라 반영한다. 원본/대상 ID·환경·적용 해시는 해당 플랫폼의 로컬 대응표에 기록한다.
4. 새 연결에서 건수·내용·첨부 연결·중복을 확인하고 그 플랫폼의 이관 결과만 보고한다. 다른 플랫폼의 백업·이관 결과로 대신하지 않는다.

두 플랫폼의 일회성 이관 실행은 구분한다. posts 전체 리셋은 실제 이관 실행 순서에 맞춰 적용하며, 플랫폼마다 자동 반복해 먼저 이관한 자료를 지우지 않는다. 백업의 증분 수집과 서버 이관은 별개다.

## 이관 검토 정보의 환경별 표시

출처 플랫폼·원 게시판 경로·원문 보기 상세는 개발에서만 표시하고 운영에서는 숨긴다. 공통 다음카페 이관 안내 박스는 유지한다. 이관 본문에 남은 단독 원본 파일명과 다운로드 파일명도 개발 검토용이며 운영 본문에서는 노출하지 않는다. 실제 첨부는 유지하고 운영에서는 일반적인 첨부 다운로드 문구로 제공한다. 원본 JSON·DB 메타데이터·실제 파일명은 삭제하지 않는다. ZIP의 비 UTF-8 한글 이름은 CP949로 해석하고 같은 원본/선택 변환 해시는 한 번만 연결한다.
