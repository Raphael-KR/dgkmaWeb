# 카카오 동의항목 심사 가이드

## 목적과 범위

이 문서는 카카오 디벨로퍼스 콘솔의 개인정보 동의항목을 현재 구현과 맞추기 위한 운영 가이드다. 현재 코드에는 생일·프로필 사진의 공통 선택 동의, 운영 앱의 카카오톡 채널 추가 상태 및 내역 선택 동의, 카카오 연결 해제를 포함한 회원 탈퇴가 구현돼 있다.

인증 정책은 [제품·개발 계획](../product/planning-proposal.md#회원과-카카오-로그인), 마지막 적용 상태와 실행 경계는 [replit.md](../../replit.md#현재-적용-상태)를 따른다. 아래는 설정·심사 절차의 기준이며 현재 환경을 재확인한 결과가 아니다. 실계정 QA는 계속 보류한다.

## 콘솔 설정값

카카오 디벨로퍼스 콘솔에서 아래 문구를 그대로 사용한다.

```text
이름: 필수 — 졸업생 명부와의 일치 여부 확인 및 동문 자격 인증
카카오계정(전화번호): 필수 — 졸업생 명부와의 일치 여부 확인 및 동문 자격 인증
카카오계정(이메일): 필수 — 회원 식별, 계정 관리 및 동문회 공식 안내
프로필 사진: 선택 — 회원 프로필 화면에 프로필 사진 표시
생일: 선택 — 회원 맞춤형 생일 축하 화면 제공
카카오톡 채널 추가 상태 및 내역: 선택 — 동문회 공지 및 경조사 알림
CI(연계정보): 사용 안 함
```

생일은 `선택 동의`로 설정한다. 동의하지 않아도 가입을 막지 않으며, 생일·생일 유형·윤달 여부가 제공될 때에만 로그인한 본인의 인앱 생일 축하 화면에 사용한다. 공개 생일 목록, 다른 회원 조회, 쿠폰, 카카오 메시지 발송에는 사용하지 않는다.

CI(연계정보)는 사용하지 않는다. 현재 단일 카카오 앱에서 서버가 처리하는 카카오 회원번호, 이메일, 비교용으로 정규화한 전화번호, PostgreSQL 동문 명부의 단일 연결로 중복 가입을 방지한다. CI를 대체 인증수단으로 설명하거나 나중에 수집한다고 표시하지 않는다.

카카오 로그인 `동의항목 → 대표 채널`에는 운영 앱에 연결된 동문회 카카오톡 채널을 등록한다. 대표 채널 설정과 별도로 `카카오톡 채널 추가 상태 및 내역(plusfriends)`은 `선택 동의`, 동의 목적은 `동문회 공지 및 경조사 알림`으로 저장한다. 친구 목록(`friends`)과 카카오톡 메시지 전송(`talk_message`) 접근권한은 사용하지 않는다. `plusfriends` 동의만으로 친구톡·알림톡 자동 발송 기능이 구현되는 것은 아니며, 실제 발송은 카카오 비즈메시지 상품·발송 승인·수신 거부·이력·실패 처리와 SMS 대체 경로를 별도로 구현한 뒤 시작한다.

공식 테스트 앱의 개발 OAuth에서는 운영 대표 채널용 `plusfriends`를 요청하지 않는다. 개발 서버에 운영 앱 키를 공유하지 않으며, 개발은 이름·프로필 사진·이메일·생일·전화번호만 요청하고 운영만 여기에 `plusfriends`를 추가한다.

## 심사 신청 입력값

카카오 디벨로퍼스의 `추가 기능 신청 → 개인정보 동의항목`에서 아래 값을 사용한다.

```text
회원가입 링크: https://dgkma.org/login
개인정보 처리방침: https://dgkma.org/privacy
회원가입 화면 또는 시나리오: 아래 현행 동의항목을 반영해 준비한 심사 자료
```

수집 사유에는 아래 문구를 사용한다.

```text
동문회 회원 가입 및 자격 인증을 위해 이름과 전화번호를 사전 보유한 졸업생 명부와 대조합니다. 이메일은 회원 식별, 계정 관리 및 동문회 공식 안내에 사용합니다. 프로필 사진은 내 정보 표시에, 생일은 로그인한 본인에게만 제공되는 생일 축하 화면에 선택적으로 사용합니다. 선택 항목에 동의하지 않아도 가입할 수 있으며 CI는 수집하지 않습니다.
```

2026-07-13에 만든 PDF·캡처는 [과거 심사 자료](../history/review-assets-2026-07-13/README.md)다. 운영 채널 선택 동의가 빠져 있으므로 현재 제출 자료로 지정하지 않는다. 새 심사 자료를 준비할 때는 필수 이름·이메일·전화번호, 선택 프로필 사진·생일과 운영 전용 채널 추가 상태·목적을 현재 안내와 맞춘다. 기존 PDF를 새 화면 확인의 증거로 사용하지 않는다.

심사용 PDF에는 실제 운영 `/login`의 데스크톱·모바일 화면과 회원가입·명부 매칭·활동 지역 입력·회원 탈퇴 시나리오만 담는다. 회원 이름, 이메일, 전화번호, 카카오 회원번호와 같은 실제 개인정보는 포함하지 않는다.

## 서비스 정합성 확인

- 로그인 화면 `/login`에는 필수 `이름, 이메일, 전화번호`, 선택 `프로필 사진, 생일, 카카오톡 채널 추가 상태 및 내역`과 각 목적이 표시돼야 한다.
- 개인정보 처리방침 `/privacy`와 이용약관 `/terms`는 필수·선택 범위, 본인 전용 생일 화면, 채널 선택 동의 목적, `내 정보 → 설정 → 회원 탈퇴` 경로를 같은 의미로 설명해야 한다.
- 카카오가 callback URL의 query로 인가 코드와 state를 전달하고, 브라우저가 인가 코드와 state를 서버에 한 번 전달한다. 서버 응답과 앱 로그에 전체 인가 코드나 토큰을 남기지 않으며, 어드민 키와 카카오 원문 사용자 응답도 반환하거나 기록하지 않는다.
- 회원 탈퇴는 `DELETE /api/users/me`에서 세션 사용자만 대상으로 하며, 카카오 연결 해제 성공 또는 이미 해제된 경우에만 종료 marker와 로컬 삭제를 하나의 트랜잭션으로 기록한다.
- 승인 거부의 신청 삭제는 카카오 unlink 성공 또는 이미 해제된 상태를 확인한 뒤 같은 카카오 신원의 신청만 삭제한다. 기존 계정·글·회비·명부 연결은 보존하고 미승인 상태를 유지한다. unlink 실패 시 신청을 보존하며 새 로그인은 관리자 승인 없이 계정을 복구하지 않는다.
- 가입 거부는 재심사를 위해 신청정보와 카카오 연결을 보존한다. 승인 취소는 계정·게시물·회비·명부 연결을 보존하며 회원 접근과 진행 중 로그인을 차단한다. 재심사는 승인 대기로만 이동하고 명부 재대조 후 별도로 승인한다.
- 종료 marker는 카카오 회원번호와 소문자 이메일의 원문 대신 각각 도메인 분리한 `SESSION_SECRET` 기반 HMAC-SHA-256 identity hash를 저장하며, 각 identity key별 종료 시각의 최신 1건만 보유한다. 종료보다 먼저 시작된 OAuth는 막고 종료 이후 새로 시작한 OAuth는 별도로 현재 회원 승인·거부 상태를 확인한다.

`/terms`에는 현재 구현과 일치하는 `카카오 로그인` 표현을 사용한다. 계약 테스트는 이전 `간편 가입` 표현의 재도입을 차단한다.

## 개인정보 국외이전 고지

공개 고지의 본문은 [개인정보 처리방침 소스](../../client/src/features/legal/privacy.tsx)의 제5조의2에서 관리한다. 이전받는 자·국가·연락처·목적·시기와 방법·보유기간·거부 방법을 이 가이드에 별도 표로 복제하지 않는다. 고지 내용과 실제 provider·처리 범위의 일치 여부는 해당 변경 작업에서 확인한다.

기존 고지 검토에 사용한 참고 자료는 다음과 같다. 이 문서 정리는 법령·계약·운영 환경을 새로 확인하거나 공개 고지를 개정한 작업이 아니다.

- [개인정보 보호법 제28조의8](https://law.go.kr/lsInfoP.do?lsId=011357)
- [Replit Data Processing Agreement](https://replit.com/dpa), [Subprocessors](https://replit.com/subprocessors), [Information Security](https://docs.replit.com/teams/information-security/overview)
- [Neon Subprocessors](https://neon.com/subprocessors), [리전 안내](https://neon.com/docs/introduction/status)

## Replit Secrets

카카오 OAuth 환경 변수와 별도로, 실제 회원 탈퇴 또는 승인 거부 신청 삭제 시 카카오 연결 해제에는 다음 서버 전용 Secret이 필요하다. 값은 문서, 클라이언트 환경 변수, 로그, 저장소에 기록하지 않는다.

- 개발: `KAKAO_DEV_ADMIN_KEY`
- 운영: `KAKAO_PROD_ADMIN_KEY`

`REPLIT_DEPLOYMENT="1"`일 때만 운영 키를 선택하고, 그 외에는 개발 키를 선택한다. `VITE_` 접두사로 만들지 않는다.

## 과거 심사·점검 기록

심사 승인, 당시 테스트·실계정 점검, DB 집계·배포 및 화면 확인 결과는 [2026-07-14 카카오 동의 심사·운영 점검 이력](../history/kakao-consent-review-2026-07-14.md)에 보존한다. 해당 이력의 완료 표시와 수치를 현행 상태나 신규 실행 승인으로 사용하지 않는다.
