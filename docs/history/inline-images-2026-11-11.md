# 게시글 본문 이미지 개발

- 목표: 무료 공식 Tiptap 확장으로 본문 이미지 붙여넣기·드래그앤드롭을 제공한다.
- 범위: Image·FileHandler 3.33.0, 기존 업로드 연결, JSON 검증·저장/복원·HTML/Markdown·상세 표시와 이미지 접근 권한.
- 완료 조건: 로컬·Replit 소스/의존성 일치, 필요한 lint·서식·앱 타입/경계와 문서 정합성 확인.
- 제외: DB DDL·기존 행 변환·실제 파일 업로드 시험·브라우저/실계정 QA·서버 재시작·Git 게시·릴리스·외부 URL 이미지 자동 수집.
- 검증: 변경 파일 정적 검사만 수행한다. 런타임·DB·업로드·붙여넣기 실제 실행은 정적 검사 통과와 구분한다.

## 결정과 보존

[제품 기준](../product/planning-proposal.md#게시글-본문-서식-2026-11-09), [편집기 계약](../reference/post-editor.md), [DB JSON 계약](../reference/database-schema.md#본문-tiptap-jsonb-계약)과 운영 문서에 범위를 먼저 반영한 뒤 구현했다. 공식 확장은 포크하거나 수정하지 않고 공개 API로 연결했다. 저장·회원 판정·업로드는 서비스 계층에서 처리한다.

본문 이미지는 content JSONB 안에만 위치와 `/objects/` 경로를 저장한다. 별도 첨부 `image_urls`와 과거 본문은 유지한다. 11월 11일 구현 당시에는 본문과 첨부 합계 20개·기존 초과 첨부 유지/축소 예외, 파일 형식·10MB, 가린 글 권한을 함께 적용했다. 제한의 후속 변경은 아래 11월 12일 기록을 따른다. 이미지 파일을 클립보드로 제공하지 않는 외부 HTML 주소를 대신 수집하지 않는다.

## 적용 상태

시작 시 로컬·Replit main은 `b4d55da121f579beba2cb2990e13b525732d3958`, 두 작업 사본의 미커밋분은 없었다. 2026-11-11 Replit 개발 워크스페이스에 코드와 의존성을 반영했다. 이번 변경은 미커밋 상태이며 GitHub push·PR·병합·릴리스는 하지 않았다. 운영 버전은 이번 작업에서 변경하지 않았다.

23:51 KST에 변경 코드·의존성·문서 25개의 SHA-256이 로컬·Replit에서 일치함을 확인했다. 최종 코드는 정적 검사 입력과 같으며, 이 결과를 추가하는 기록 문서만 후속 반영한다. 최종 파일별 해시와 원격 Git 상태는 `.superpowers/inline-images-20261111/final-sync.json`에 보존한다.

- 공식 `@tiptap/extension-image`·`@tiptap/extension-file-handler`를 `3.33.0`으로 설치했다. lockfile에는 공식 peer인 `@tiptap/extension-text-style@3.33.0`도 추가되며 세 패키지 모두 MIT다. 기존 Tiptap 버전·단축키·패키지 소스를 변경하지 않았다.
- `editor-images.ts`는 공식 FileHandler의 파일 이벤트와 Image 블록 삽입만 연결한다. `use-post-images.ts`는 작성·수정 화면의 기존 업로드 요청과 형식·용량·합계 개수 제한을 공유한다. 업로드 중 본문/모드·게시·초안 닫기를 막고 성공한 파일만 삽입하며 실패를 알린다.
- 편집기·저장 정규화·React 표시기·HTML/Markdown은 공통 공식 Image 스키마를 사용한다. 별도 첨부를 본문에 복제하지 않는다. 목록·검색은 기존 text 노드 추출을 유지한다. 이미지가 Markdown에서 표현되지 않는 속성을 가지면 기존 왕복 비교와 손실 안내를 적용한다.
- 저장 API는 본문과 첨부의 이미지 경로·개수·열람 권한을 함께 검사한다. 파일 열람의 게시글 참조 조회는 JSONB 이미지 노드도 포함한다. 작성자 수정·삭제와 관리자 가리기, 경조사 생성·확인 후 게시 정책은 유지한다.
- DB 컬럼·제약·마이그레이션·기존 행은 변경하지 않았다. 이미지 파일과 토큰을 JSONB에 넣지 않으며 임시 업로드를 자동 삭제하는 기능도 추가하지 않았다.

## 실제 수행한 정적 검사

환경은 Replit `/home/runner/workspace`, Node `v20.20.0`, npm `10.8.2`다. 2026-11-11 23:46~23:47 KST에 검사했다. 파일 목록·명령·시각·종료 코드·출력·입력 SHA-256은 양쪽 워크스페이스의 `.superpowers/inline-images-20261111/checks.json`과 `checks-final.json`에 보존한다. 로컬 npm 의존성으로 앱 검사를 대신하지 않았다.

| 검사 | 선택 이유·명령 | 결과와 재사용 |
|---|---|---|
| ESLint | 변경 TS/TSX 14개에 `./node_modules/.bin/eslint <파일 목록>` | 오류·경고 없이 통과. 아래 반복문을 수정한 2개만 다시 검사했고 나머지 12개는 동일 해시의 첫 결과를 사용 |
| 서식 | 변경 TS/TSX·CSS 15개에 `./node_modules/.bin/prettier --check <파일 목록>` | 통과. 수정한 2개 재검사, 나머지 13개는 입력 동일 |
| 앱 타입·의존 경계 | 공통 문서·입력 계약과 편집기 연결 변경에 `npm run check` | 최종 통과. 경계 검사 앱 파일 245개, sandbox 제외 |

첫 타입 검사에서는 현재 TypeScript target이 NodeList·ArrayIterator의 직접 순회를 허용하지 않아 오류 2건이 나왔다. NodeList는 `Array.from`, 업로드 파일 목록은 인덱스 반복으로 수정하고 통과했다. 검사 기준·tsconfig를 완화하지 않았다. npm 실행 시 기존 셸의 `LC_ALL=C.UTF-8` locale 경고가 있었으며 타입·경계 검사는 종료 코드 0으로 끝났다.

테스트 타입·빌드·단위/HTTP/DB 테스트는 실행하지 않았다. 테스트 파일이나 테스트 전용 타입·도구는 변경하지 않았고 배포 산출물을 만드는 작업도 아니다. 정적 검사 결과를 실제 업로드·열람 성공으로 해석하지 않는다.

## 남은 확인 범위와 제약

- 브라우저에서 스크린샷/파일 붙여넣기·외부 드롭·편집기 내부 이동·업로드 중 조작·실패 후 재시도·저장 후 재진입을 실제 실행하지 않았다. 실제 Object Storage 업로드, DB 이미지 참조 조회, 가린 글의 파일 응답도 실행 확인하지 않았다.
- 파일과 HTML이 함께 제공되면 텍스트 서식 뒤에 업로드에 성공한 이미지 블록을 붙인다. 웹페이지의 원래 이미지 배치나 이미지 URL만 있는 외부 문서를 자동으로 가져오지 않는다. 파일 없는 HTML의 미지원 이미지 주소는 제외 사실을 알린다.
- 공식 Image의 크기 조절 핸들은 켜지 않았다. 본문 폭에 맞추는 표시는 공통 CSS를 사용한다. 사진 내용 분석·대체 텍스트 자동 작성·AI 호출·새 단축키는 추가하지 않았다.
- 서버 재시작·운영 DB 작업·Republish·실계정 QA는 수행하지 않았다. 개발 코드 반영과 실행 중 서버의 새 동작 확인을 구분한다.

## 2026-11-12 이미지 제한 변경

사용자 결정에 따라 새 파일 업로드는 파일당 5MB, 본문·별도 첨부 합계는 40개로 변경했다. 클라이언트 파일 검사·안내, 서버 업로드·서명 검증, 게시글 생성·수정의 합계 검사는 기존 공통 상수를 함께 사용한다. 기존 파일·게시글과 초과 첨부 유지/축소 예외는 보존하며 DB 구조는 변경하지 않았다.

제품 정책과 DB 입력 계약을 먼저 갱신한 뒤 `shared/contracts/uploads.ts`의 공통 상수 2개를 변경했다. 2026-11-12 00:38 KST Replit 개발 소스에 반영하고 해당 파일의 ESLint·Prettier 및 `git diff --check`가 모두 종료 코드 0으로 통과했다. 현행 문서의 이전 10MB·합계 20개 표현과 호출부를 대조했다. 숫자 값만 바뀌었으므로 타입·전체 회귀·빌드 검사는 추가하지 않았다. 결과와 입력 해시는 `.superpowers/image-limits-20261112/checks.json`에 보존한다.

로컬·Replit 소스와 기록을 맞추며 기존 미커밋 변경은 유지했다. 실제 업로드 시험·서버 재시작·DB 변경·Git 게시·배포·실계정 QA는 수행하지 않았다.
