# 전체 코드 정리

2026-11-10 사용자의 전체 코드 정리 요청에 따른 기록이다. [유지보수 정책](../product/planning-proposal.md#6-기존-기능의-보완과-정리), [구조 기준](../architecture/project-structure.md), [Replit 정적 검사 절차](../../replit.md#개발-직후-정적-점검)를 적용했다.

- 목표: 특정 기능에 한정하지 않고 프로젝트 소스 전반의 가독성·중복·책임 분리를 정리한다.
- 범위: 시작 사본의 코드 375개와 설정·템플릿. 고정 버전 Prettier 도입, JS/TS/TSX·CSS 서식 통일, 로그인 복귀 경로 공통화, 큰 OAuth 검사 파일의 대역·주제 분리와 불필요한 설명 정리.
- 완료 조건: 문자열·화면 문구·API·권한·보안·트랜잭션·호환 계약과 기존 미커밋 작업을 보존하고 로컬·Replit 개발 사본에 반영한다. 파일을 모두 변경하는 것을 완료 조건으로 삼지 않는다.
- 제외: DB 작업·서비스 실행·외부 기능 호출·빌드·재시작·배포·실계정 QA·Git 게시. 작성기 원본 3개·SQL 전환 자료·생성물·사용 중인 sandbox와 자산은 보존한다.
- 검증: Replit 타입·lint·의존 경계·서식과 AST/리터럴 비교, CSS/Python/Shell 구문·문서 링크를 필요한 범위에서 정적으로 확인한다. 실행형 테스트는 수행하지 않는다.

## 적용·검사 결과

구조 기준·Replit 절차·스크립트 안내를 먼저 갱신한 뒤 구현했다. 시작 사본은 관리 파일 503개·코드 375개였고, 새 모듈·설정·기록을 포함한 결과는 관리 파일 513개·코드 382개다. 이번 작업은 322개 파일을 변경·추가했으며 삭제는 없다. 이전 작업의 미커밋·삭제·미추적 상태는 보존했다.

- **공통 서식:** [공식 설치 지침](https://prettier.io/docs/install)에 따라 개발 의존성 `prettier`를 `3.9.10`으로 고정했다. JS/TS/TSX·CSS 365개 중 311개를 정리하고 나머지는 기존 서식을 유지했다. `npm run format`과 `npm run format:check`를 추가했다. 문자열 안의 SQL·프롬프트, CSS 클래스 순서와 런타임 의존성 선언은 유지했다.
- **로그인 복귀:** `client/src/features/auth/lib/return-path.ts`로 저장 키·경로 소비를 모았다. 로그인 창, 카카오 콜백, 지역 선택 화면이 공유한다. 상대 경로 검사·저장값 제거·오류 발생 시 기존 흐름은 유지했다.
- **OAuth 검사 구조:** 1,368줄의 `kakao-oauth-routes.test.ts`를 등록 진입점, 공통 대역, 주제별 5개 모듈로 분리했다. 각 모듈은 118~296줄이다. 기존 27개 사례의 내용·등록 순서와 한 파일 단위의 실행 격리는 유지했다.
- **주석·계약 검사:** 자명한 화면 설명과 중복 주석을 정리했다. 관리자 화면의 파일 기반 계약 검사에서 한 줄 표기에 의존하던 쿼리 구간·DTO import 판정을 공백과 줄바꿈에 영향받지 않게 수정했다. 구간 누락도 명시적으로 실패한다.

### 보존한 부분

- Python 4개·SQL 11개·Shell 1개는 시작 사본과 동일하다. 검증된 작성기 원본 3개, DB 전환 자료와 보존 사유는 변경하지 않았다.
- `artifacts/mockup-sandbox`는 사용 중인 설계 미리보기 서비스다. 소스 서식만 통일하고 별도 의존성·타입 검사·실행 구성은 유지했다. 생성 파일 `src/.generated/mockup-components.ts`는 포맷에서 제외했다.
- 가장 큰 자체 검사 파일인 `kakao-termination-race.test.ts`는 세 시나리오가 DB pool과 종료 정리를 공유하므로 같은 실행 단위로 유지했다. sandbox의 공식 UI 기반 코드와 독립 진단 스크립트도 줄 수만을 이유로 분할하지 않았다.
- 초기 HTML의 복구 화면·인라인 스타일/스크립트는 앱 번들 실패 시에도 동작해야 하므로 독립된 구조를 유지했다. 제품 정책·권한·DB 스키마·수집기 실행 경계는 바꾸지 않았다.

### 실제 검사

2026-11-10 Replit 개발 워크스페이스에서 다음 정적 검사를 수행했다.

| 검사 | 결과 |
|---|---|
| `npm run check` | 타입·의존 경계·런타임 의존 순환 검사 통과. 경계 대상 앱 파일 230개 |
| `npm run check:tests` | 검사 코드 타입 통과. 파일 계약 보완 후 다시 통과 |
| `npm run lint` | 통과. 후속 변경 파일도 별도 lint 통과 |
| sandbox `npm run typecheck` | 통과 |
| `npm run format:check` | 통과. 후속 변경 파일도 서식 검사 통과 |
| 서식 보존 비교 | TS/JS 227개 원본·변환 AST, TSX 135개 JSX 변환 AST 일치. 인접 JSX 문자열은 공백을 보존해 비교. CSS 3개 구문 및 포맷터 AST 확인 |
| 모듈 분리 보존 비교 | 기존 OAuth 27개 사례·대역·import 대상·등록 순서, 로그인 복귀 흐름 등 43개 정적 비교 통과 |
| 파일 기반 계약 | 문서·관리자 화면·라우트·개인정보 로그 계약 20항목 확인. 줄바꿈 의존 3건 보완 후 해당 파일의 4항목 재검사 통과 |
| 기타 | Python 4개 `ast.parse`, Shell `bash -n`, Markdown 링크·앵커, `git diff --check` 통과 |

초기 Prettier `--debug-check`는 BigInt AST 직렬화 오류와 한 파일의 출력 멱등성 차이로 실패했다. BigInt 코드를 변경하지 않고 TypeScript AST 비교로 대체했으며, 해당 파일은 안정된 서식 결과와 최종 `format:check` 통과를 확인했다.

코드와 기록은 로컬 및 Replit 개발 사본에 반영했다. 로컬 main `d7184ca`, Replit 개발 main `5872027`의 Git HEAD는 유지했다. 커밋·push·PR·병합·DB 작업·서비스 실행·빌드·재시작·배포·실계정 QA는 수행하지 않았다. 정적 검사 결과는 실행 동작의 재검증을 뜻하지 않는다.
