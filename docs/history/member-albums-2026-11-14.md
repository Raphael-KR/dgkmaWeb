# 회원 사진첩과 다음카페 개발 이관 — 2026-11-14

## 확정 범위

사용자는 다음카페 동창회앨범 52건을 로그인한 승인 회원만 볼 수 있는 역사관 사진첩으로 이관하도록 결정했다. 이어서 역대임원진 31건은 기존 공개 임원 기록에 반영하도록 허용했다. 일반 글은 작성자 계정 없이 기존 DB에 등록하고, 현재 회원과 임의로 연결하지 않도록 결정했다.

[제품 계획](../product/planning-proposal.md), [이관 기준](../product/community-archive-migration-proposal.md), [콘텐츠 계약](../reference/heritage-content.md), [DB 구조](../reference/database-schema.md), [DB 운영](../runbooks/database-operations.md), [Replit 절차](../../replit.md)를 먼저 갱신한 뒤 구현했다. PostgreSQL 스키마 변경·운영 반영·실계정 QA는 포함하지 않는다.

## 개발 환경 반영

| 대상 | 반영 결과 | 확인 방법 |
|---|---|---|

| 일반 글 첨부 | 본문 이미지 1개·HWPX 11개, 총 12개 | 기존 파일 형식·크기·내용 검증과 Storage 재다운로드 SHA-256 일치 |

사진첩 Storage 적용은 2026-11-14 02:45 KST, 일반 글 DB 적용은 03:00 KST에 완료했다. 로컬 SQLite는 총 169개 원본의 개발 적용 대응표를 기록하고 `integrity_check=ok`를 확인했다. 임원 자료의 ‘적용’은 개발 소스 반영을 뜻하며 운영 공개 완료를 뜻하지 않는다.

일반 글은 기존 nullable `posts.author_id`를 NULL로 두었다. 새 회원 계정·테이블·컬럼·게시판은 만들지 않았다. 원작성자·작성일·출처는 본문에 보존하고 계정 표시는 ‘작성자 계정 미연결’로 변경했다. 일반 작성 API와 수정·삭제·가리기 권한은 유지했다.

사진첩 목록은 비공개 Object Storage의 development 영역에 저장했다. 공개 번들·정적 경로에서 앨범 자료를 제거하고, 서버의 기존 승인 회원 확인 뒤 목록·사진을 제공하는 `/api/heritage` 경로를 추가했다. 일반 `/objects/` 경로로 앨범 파일을 직접 읽지 못하게 했다. 최초 HTML·클라이언트 메타데이터를 `noindex, nofollow`로 맞추고 사이트맵에서 제외했다. 공개 기록에는 제목·대표 사진 대신 ‘관련 사진첩’ 링크만 남겼다.

카페 앨범에 일반 글의 이미지 40개 제한을 적용하거나 앨범을 분할하지 않았다. 최근 목록은 기존 최근 5개 연도 정책을 유지한다. 오래된 이관 앨범은 ‘전체’ 또는 ‘이전 연도’에서 선택한다.

임원 사진은 19개 항목에 연결하며 같은 파일을 공유하는 항목을 제외한 JPEG 17개를 공개 소스에 추가했다. 원본의 ‘X Image’ 대체 그림 12개는 인물 사진으로 등록하지 않았다. 회장 기간은 확정된 기존 명단을 유지하고, 회장 이외 임원의 카페 기간은 출처를 붙여 표시했다. 현 임원 자료는 유지했다.

## 보존과 변환 한계

- 일반 글 86건의 원문 텍스트는 공백 차이를 제외하고 변환 결과와 대조했다. 문단·표·기본 인라인 서식·링크를 Tiptap으로 변환했다. 옛 글꼴·색상·상첨자 서식은 지원 형식으로 옮기지 않았으며 상첨자 5곳의 글자는 일반 텍스트로 보존했다.
- 원본에서 확보하지 못한 일반 글 이미지 6개는 누락 안내로 표시했다. 백업에서 ‘이미지 저장 438개’로 집계한 항목 중 12개는 위 임원 대체 그림이며 실제 인물 사진이 아니다.
- `dbpl-35.hwpx`는 사용자가 제공한 한컴 변환본을 사용했다. 나머지 변환물의 기존 검사 상태와 `dbpl-33-1.hwpx`의 외부 PCX 참조 5개 등 미확인 사항은 로컬 변환 기록에 유지했다. 이번 형식 검사와 업로드 성공을 렌더 대조 성공으로 보고하지 않는다.
- 원문 백업·로컬 SQLite·변환 원본은 Mac에 보존했다. Replit에는 선택한 최종 본문·자료·허용 첨부만 전송했다. 원문 백업·SQLite·쿠키·토큰은 업로드하지 않았다.

## 실제 검사와 미검증 범위

2026-11-14 Replit 개발 워크스페이스에서 다음 정적 검사를 수행했다.

- `npm run check`: 타입·의존 경계 검사 통과, 앱 파일 277개.
- 변경한 TypeScript/TSX 파일 범위의 ESLint와 Prettier 검사 통과.
- `node scripts/check-heritage-content.mjs`: 공개 자료 검사 통과, 임원 15개 대수.
- `node --import tsx scripts/check-heritage-catalog.ts <catalog.json>`: 앨범 52건·사진 항목 406개의 구조·참조 검사 통과. Storage/API를 호출하지 않는 검사다.
- `git diff --check`와 변경 문서의 로컬 링크·정합성 확인.

실제 이관에서는 별도로 기존 Tiptap 정규화·저장 스키마, 첨부 검증 코드를 사용하고 DB 새 연결·Storage 재다운로드로 결과를 확인했다. 이 데이터 쓰기·조회는 위 정적 검사와 구분한다. 원본/대상 ID·적용 해시·영수증·소스 대조 결과는 Git 제외된 `local-backups/community/migration/`와 `archive.sqlite3`에 보존한다.

개발 소스는 Replit에 반영했으나 새 API 적용을 위한 서버 재시작·회원 API HTTP 실행·브라우저 화면·실계정 QA는 수행하지 않았다. 코드·자료 검증으로 로그인 차단이나 사진 확대의 실제 실행 확인을 대신하지 않는다. 빌드·운영 DB/Storage 변경·Republish·commit·push·PR·merge도 수행하지 않았다.
