# 전체 폭 반응형 개발 기록

- 목표: 커뮤니티 화면의 불필요한 좌우 공백을 줄이고 화면의 가용 너비를 사용한다.
- 범위: 공통 컨테이너·하단 메뉴 CSS와 게시글·경조사 본문 표시기의 읽기 폭.
- 완료 조건: 모바일·태블릿·PC의 공통 여백, 기존 열 전환, 장문 읽기 폭을 코드에 반영하고 Replit 개발 사본의 정적 검사를 통과한다.
- 제외: DB·권한·저장 계약·메뉴 동작 변경, 서버 재시작·운영 배포·실계정 QA.
- 검증: 변경 TSX lint·코드/CSS 서식, Tailwind/PostCSS 정적 처리, 문서 링크·공백과 소스 일치 확인. 타입·저장 계약과 테스트는 변경하지 않으므로 전체 타입·회귀·배포 빌드는 추가하지 않는다.

## 결정과 적용 범위

사용자가 가용 너비 100%·모바일 16px/태블릿 24px/PC 32px 여백, 기존 1열·다열 전환, 전체 폭 하단 메뉴, 장문 본문의 별도 읽기 폭 검토안을 승인했다. 실행 기준은 [제품 정책](../product/planning-proposal.md#회원-커뮤니티-반응형-화면-2026-11-09)과 [Replit 개발 범위](../../replit.md#전체-폭-반응형-개발-범위)에 먼저 반영했다.

기존 `member-container`는 768px 미만에서 최대 28rem, 그 이상에서 80rem이었다. 하단 메뉴 내부도 28rem으로 제한했다. 이 바깥 폭 제한과 전용 토큰·중복 미디어 규칙을 제거하며 공개·회원 헤더/푸터와 회원 본문은 기존 공통 여백 토큰을 재사용한다. 기존 홈·게시판·명부·검색·내 정보의 반응형 grid는 유지한다.

장문 본문은 공통 `site-reading-width`와 공개 안내의 48rem 기준을 공유한다. 게시글 상세·경조사 미리보기에는 표시기에서 적용하고, 편집기에 함께 쓰는 `post-body` 서식 클래스 자체에는 폭 제한을 넣지 않는다. 회칙·규정·약관과 대화상자·로그인 폼의 용도별 최대 폭은 유지한다.
