# 게시글 입력·SEO 등 5개 항목 정리

2026-11-10 KST 사용자 요청에 따라 직전 검토의 정리 대상 5개를 반영했다. 권리회원 정책은 사용자에게 별도로 질문했고 “공개 규정 기준으로 정리”를 선택받아 [결정안](../decisions/0005-membership-public-regulations.md)에 기록했다. 이 문서는 당시 적용·검사 기록이며 현재 정책은 [제품 계획](../product/planning-proposal.md), 환경 상태는 [replit.md](../../replit.md)를 따른다.

## 적용 순서와 범위

제품 계획·구조·DB 계약 설명·개발/DB 런북·Replit 문서와 결정안을 먼저 갱신해 Replit 개발 사본에 적용했다. 그 뒤 소스를 변경했다. 각 전송 전에 기존 파일 해시를 비교했으며 다른 미커밋 작업을 덮어쓰지 않았다.

| 항목 | 반영한 내용 |
|---|---|
| 글쓰기 초안 수명 | `use-create-post.ts`가 입력·업로드 묶음·게시 요청·초기화를 담당한다. 작업 중 닫기·입력 변경·중복 요청을 막고 취소·닫기·성공을 같은 초기화로 처리한다. 실패하면 입력을 유지한다. UI는 `create-post-dialog.tsx`에 둔다 |
| 작성·수정 입력 계약 | 공통 제목 1~300자·이미지 20개·오브젝트 경로를 `post-input.ts`에서 검증한다. 작성 API의 문자열 강제 변환과 약한 별도 경로 검사를 제거했다. 기존 제목 그대로 유지·첨부 유지/감소는 서버가 읽은 현재 글을 기준으로 허용하며 경로·권한·revision에는 예외를 두지 않는다 |
| 공개 SEO | `shared/public-pages.ts`의 13개 경로 정의를 최초 HTML과 클라이언트가 공유한다. 규정 페이지를 포함하며 `/about`의 중복 canonical을 제외한 12개 주소로 사이트맵을 구성한다. 사이트맵·robots는 서버의 공개 경로에서 제공하고 기존 정적 사본 2개는 제거했다. 사이트맵 URL은 `https://dgkma.org/` 기준 절대 주소다 |
| 정적/실행형 검사 분리 | 전화번호 정규화의 기존 함수 본문을 DB 의존성이 없는 `server/lib/phone-normalization.ts`로 옮겼다. 기존 단위 사례와 입력은 별도 `phone-normalization.test.ts`로 이동했다. `member-deduplication.test.ts`에는 파일 읽기 계약만 남겼다 |
| 경조사 코드 | 경사 반환 뒤의 중복 부고 조건·도달하지 않는 예외를 제거했다. 필드 출처를 값 정규화·입력 일치·수집 근거 일치로 나누고 압축된 표현을 정리했다. 질문·작성기 입력·게시 개인정보 조건과 순서는 유지했다 |

새 입력 제한을 초과하는 기존 값을 일괄 변경하지 않았다. 기존 글 보존 분기는 작성자에게서 받은 기준값이 아니라 서버의 현재 행을 사용한다. 첨부 유지·감소도 각 경로의 문법과 열람 권한을 통과해야 한다. 현재 `payments` 테이블과 5만 원 등급 계산은 그대로이며 공개 규정에 맞추는 후속 구현은 이번 범위가 아니다.

## 실제 정적 검사

검사 환경은 `/home/runner/workspace` Replit 개발 워크스페이스다.

- `npm run check`: 통과. 앱 타입과 223개 앱 소스의 의존 경계·순환 참조를 검사했다.
- `npm run check:tests`: 통과. 분리·수정한 기존 검사 파일을 포함해 타입만 확인했다.
- 변경 JS/TS 33개 ESLint: 통과. 이후 TypeScript 타깃 호환 표현 2개와 import 서식 1개를 고쳐 해당 3개 lint 및 타입 검사를 다시 통과했다.
- 최초 앱 타입 검사에서 Unicode 정규식 리터럴과 Set 전개가 현재 타깃과 맞지 않았다. 기존과 같은 `RegExp` 생성자·`Array.from` 표현으로 고쳤다. 컴파일 설정이나 규칙을 완화하지 않았다.
- 앱을 import하지 않는 소스 AST 대조로 인증 보조 선언 10개, 게시글 권한 보조 함수 3개, 경조사 질문 순서·작성기 입력·회원 조회 호출이 보존됨을 확인했다. 순수 전화번호 모듈의 runtime import는 0개다.
- 공개 화면 13개의 반환 본문, 기존 권리회원 판정·게시 저장·경조사 권한·경사 작성·오브젝트 권한·DB 스키마 파일 7개가 시작 사본과 같음을 확인했다. 공개 페이지 메타데이터 변경을 규정 본문 개정으로 취급하지 않는다.
- Markdown 77개의 내부 링크 700개·앵커 256개에서 오류가 없었다. 최종 파일 해시와 `git diff --check`도 로컬·Replit에서 확인했고 불일치·공백 오류가 없었다.

파일 기반 계약을 실행하려던 `node --test` 명령은 자동 승인 검토가 실행형 검사로 판단해 실행 전에 거부했다. 그 명령을 재실행하거나 우회하지 않았다. 타입·lint, 소스 텍스트/AST 비교와 문서 링크 확인만 수행했으며 Node test runner·단위·통합 검사는 실행하지 않았다. 이 기록을 기존 검사 사례의 실행 통과로 해석하지 않는다.

## 보존 확인과 적용 상태

로컬은 `main d7184ca5238e0cdc3e91515ac0616e3b33332f41`, Replit 개발은 `main 587202723e943cb2cc9c3d3e1daf022770f33342`를 유지한다. 시작 사본 기준 기존 파일 37개를 수정하고 정적 메타데이터 사본 2개를 제거했으며 코드·결정·이력 7개를 추가했다. 기존 454개 파일은 그대로다. 관리 파일은 총 498개이며 로컬·Replit의 파일 해시가 모두 일치했다. Git 이력 차이를 소스 내용 불일치로 혼동하지 않는다.

DB 연결·DDL·데이터 변경, 회원 등급 재계산, 서버 재시작·빌드·배포, 외부 수집·OpenAI 호출, 실계정 QA, 커밋·push·PR·병합은 수행하지 않았다. 브라우저에서 취소·업로드·작성/수정 동작이나 실제 HTTP 메타데이터 응답은 확인하지 않았다. 정적 검사 통과가 그 실행 결과를 대신하지 않는다.
