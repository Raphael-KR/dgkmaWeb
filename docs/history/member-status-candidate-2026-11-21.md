# 동문 상태와 변동 이력 개발 전환

2026-11-21 Replit 개발 워크스페이스에서 실행 중인 서버와 분리한 소스로 검사했다. [회원 상태 설계](../product/pre-migration-database-design.md#탈퇴)와 [개발 전환 SQL](../../scripts/member-status-development.sql)에 따라 가입·심사·탈퇴 처리와 사망 상태의 접근 차단을 준비했다. 탈퇴·가입을 추정해 과거 이력을 채우지 않는다.

- 앱과 테스트 소스의 TypeScript 검사, 모듈 경계 검사(앱 파일 279개), 변경된 TypeScript/TSX 16개 파일의 ESLint와 Prettier 검사를 통과했다.
- PostgreSQL 파서로 회원 상태 전환과 기수 등록 SQL의 미리보기·적용 분기 구문을 확인했다. SQL을 DB에 보내거나 행·제약을 대조한 결과는 아니다.
- 로컬과 Replit 검사본의 소스·SQL·기준 문서 24개를 바이트 단위로 대조했다. 개발 서버 활성화, DB 적용, 운영 반영과 실계정 QA는 보류했다. 실제 전환을 승인하면 [개발 런북](../runbooks/database-operations.md#회원-상태와-변동-이력-전환)에 따라 기존 상태와 신청 충돌 건수부터 확인한다.

## 최초 신청 시각 보존과 사망 기록

2026-11-21 Replit에서 후속 변경을 정적으로 검사했다. 같은 신청의 재로그인은 최초 접수 시각을 유지한다. 상태 이력은 기존 DB 트리거에서 기록하며, 사망 전환의 이력명은 ‘사망 기록’이다. 이력 시각은 DB가 기록한 시각이고 확인된 실제 사망일은 명부 메모에 둔다.

- 앱·테스트 TypeScript 검사, 모듈 경계 검사(앱 파일 279개), 변경한 TypeScript 2개 파일의 ESLint와 Prettier 검사를 통과했다.
- 회원 상태 전환 SQL의 미리보기 6문과 적용 14문을 파싱하고 내부 PL/pgSQL 구문까지 확인했다. 소스·SQL·기준 문서 7개의 SHA-256이 로컬과 Replit 검사본에서 일치했다. 실제 DB 전환과 동시 재로그인 시험은 수행하지 않았다.

## 개발 DB 전환 미리보기

Replit 개발 DB `heliumdb`에는 동문 3,458명, 가입 심사 0건이 있었다. 미리보기에서 미가입 3,302명과 사망 95명을 분류했다. 기존 상태가 ‘정회원’인 61명은 전환 규칙에 없어 보류했다. 이 중 60명은 카카오 연결과 가입 승인이 모두 없고 1명은 둘 다 있다. 미리보기는 롤백으로 끝났고 변경 전 스키마 카탈로그 지문은 직전 개발 기록과 일치했다.

## 개발 DB 전환과 서버 기동

2026-11-21 옛 명부 상태 ‘정회원’ 61명을 기존 카카오 연결과 가입 승인으로 분류했다. 60명은 미가입, 승인된 1명은 가입 완료로 전환했다. 미분류가 없는 미리보기를 확인한 뒤 개발 앱이 정지한 상태에서 전환 SQL을 한 트랜잭션으로 적용했다.

새 개발 DB 연결에서 동문 3,458명 중 미가입 3,362명, 가입 완료 1명, 사망 95명을 확인했다. 승인 불일치와 과거 이력 소급 생성은 각각 0건이었다. 회원별 승인·카카오 연결·관리자 여부·가입일과 회비 기록의 전후 지문이 일치했다. 관리자 1명, 납부 및 가입 심사 기록 각 0건이다. 상태와 이력 컬럼, CHECK 3개, 활성 트리거 1개와 그 함수를 확인했다. 전체 [스키마 카탈로그](../reference/database-schema.md#기준-소스와-마지막-db-관찰)도 갱신했다.

Replit 개발 워크스페이스에 전환 파일 19개를 반영하고 SHA-256을 대조했다. 개발 앱을 `npm run dev`로 기동한 뒤 별도 SSH 연결에서 5000 포트의 공개 `/about`은 200, 비로그인 `/api/auth/me`는 401을 확인했다. 실제 가입·탈퇴·사망 이벤트 생성, 운영 반영과 실계정 QA는 수행하지 않았다.

## 사무국 사망 처리 CLI

2026-11-21 Replit 개발 워크스페이스에 [사망 처리 CLI](../../scripts/record-alumni-death.ts)와 [사무국 절차](../runbooks/database-operations.md#동문-사망-처리)를 반영했다. 기존 상태 이력 트리거를 재사용한다. DB 스키마 변경이나 서버 재시작은 없었다.

CLI 타입 검사와 ESLint·Prettier를 통과했다. 기수 등록 SQL의 미리보기 7문·적용 8문과 각 분기의 PL/pgSQL 블록 2개를 DB 연결 없이 파싱했다. 코드·기준 문서 6개의 SHA-256이 로컬과 개발본에서 일치했다. 실제 동문에 대한 미리보기·변경, 외부 문자 발송, 운영 반영과 실계정 QA는 수행하지 않았다.
