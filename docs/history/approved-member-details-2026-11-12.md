# 인증 완료 회원 정보 표시

- 목표: 관리자가 인증 완료 회원의 제공 정보와 연결된 명부 항목을 모두 확인할 수 있게 한다.
- 범위: 관리자 목록 조회 계약·저장소 조회·화면, 제품·운영·자료 계약 문서.
- 완료 조건: 회원 정보와 실제 연결된 명부 12개 항목의 출처를 구분하고 누락값·연결 없음을 표시하며, Replit 개발 소스 반영과 필요한 정적 검사를 마친다.
- 최초 구현의 제외: DB 구조·회원 데이터·승인 상태 변경, 운영 릴리스·개발 서버 재시작·실계정 QA. 후속 요청에 따른 재시작은 아래에 구분한다.
- 검증: 변경 파일 lint·서식, 앱 타입·의존 경계, 공용 계약의 영향을 받는 테스트 타입, 문서 링크·`git diff --check`. DB·단위 테스트·브라우저·빌드는 실행하지 않는다.

## 결정과 구현 범위

사용자가 2026-11-12 검토안을 승인했다. [회원 정책](../product/planning-proposal.md#회원과-카카오-로그인)을 먼저 갱신하고 [개발 운영](../../replit.md#인증-완료-회원-정보-개발-범위)·[저장 계약](../reference/database-schema.md#table_row-users)을 맞췄다.

인증 완료 목록은 현재 `users` 저장값의 이름·이메일·전체 전화번호·프로필 사진·생일·양력/음력·윤달 여부·활동지역을 제공한다. 연결 명부는 `matched_user_id`로 조회하고 12개 관리 항목을 모두 표시한다. 빈 값·연결 없음·여러 연결 행을 구분하며 카카오 내부 ID·인증정보·가입 JSON은 내보내지 않는다. 대기·거부의 후보 검색과 승인·취소·재심사·삭제 처리, 관리자 권한은 유지한다.

## 적용과 검사

시작 기준은 로컬 main `e58033fff31d878c86123e49da11c8dcf2f9df04`와 운영 `4.0.0`이다. 변경 전 로컬·Replit 개발 사본은 같은 HEAD·clean 상태였으며 파일 589개의 해시가 일치했다. 문서를 먼저 반영한 뒤 변경 코드·문서를 해시 대조 방식으로 Replit 개발 사본에 직접 반영했다. GitHub와 운영에는 아직 반영하지 않았다.

- 서버는 인증 완료 회원의 허용 필드만 조회하고 `matched_user_id`로 연결 명부를 한 번에 가져온다. 이름·전화번호가 달라도 실제 연결을 표시하며, 연결 없음·복수 연결을 숨기지 않는다. 자동 가입자도 동일하게 처리한다.
- 화면은 `회원 정보`와 `연결된 동문 명부`를 구분한다. 공통 Avatar의 중앙 크롭과 명부 필드 표시 컴포넌트를 재사용한다. 명부 선택 컬럼도 공통화했다. 이전 `memberReviewRegistration` 투영과 인증 완료의 후보 검색·불필요한 대조 표시는 제거했다.
- 현재 회원 정보를 심사 신청으로 구성하는 `memberRegistrationData`는 승인 취소에서 실제 사용하므로 보존했다. 기존 관리자 미들웨어·캐시 금지 응답·상태 결정·일반회원 조회 범위는 유지했다.
- 기존 후보 응답의 캐시가 새 회원 상세 응답과 섞이지 않도록 인증 완료 키를 `member-details`로 구분했다. 기존 API 경로 접두사로 하는 상태 결정 후 갱신은 유지한다.
- 2026-11-12 07:30 KST Replit Node.js `20.20.0`에서 변경 코드 12개의 ESLint·Prettier, `npm run check`(앱 타입·의존 경계 276개 파일), `npm run check:tests`가 통과했다. 검사 전후 입력 해시가 같았다.
- 캐시 키 후속 변경 후 07:32 KST 해당 파일의 lint·서식과 앱·테스트 타입 검사를 다시 통과했다. 같은 소스인 나머지 11개 파일의 lint·서식은 앞선 결과를 재사용한다. 기존 셸의 `C.UTF-8` locale 경고 외 오류는 없다.
- 변경 문서 7개의 로컬 링크 330개·앵커 105개와 `git diff --check`가 통과했다. 코드·검사·직접 반영 근거는 Git 제외 경로 `.superpowers/approved-member-details-20261112/`에 보관한다.

최초 구현에서는 DB 조회·변경, 단위/통합 테스트·빌드·브라우저·실계정 QA를 실행하지 않았다. 당시 개발 서버를 재시작하지 않아 새 API의 실행 반영도 확인하지 않았다. 커밋·push·운영 배포는 수행하지 않았다.

## 후속 개발 서버 재시작

2026-11-12 사용자 요청으로 07:51 KST Replit 개발 앱만 재시작했다. 기존 `npm run dev`와 자식 프로세스를 SIGTERM으로 종료하고 같은 명령·개발 환경으로 새 프로세스(PID 7751)를 시작했다. 재시작 전 로컬에서 반영한 파일 594개의 해시가 Replit 사본과 일치했으며, 미커밋 변경과 목업 서비스는 보존했다.

개발 DB 연결·기존 세션 인덱스 확인·5000 포트 기동 로그에 경고나 치명 오류가 없었다. 개발 서버 내부 HTTP에서 `/about`은 HTML 200, `/api/admin/pending-registrations?status=approved`는 비로그인 JSON 401이었다. 실제 회원 자료 조회·사진 표시·클릭 동작·실계정 QA는 확인하지 않았다. 앱 소스를 변경하지 않아 위 정적 검사는 반복하지 않았으며, 별도 DB 작업·운영 배포·커밋·push는 수행하지 않았다. 실행 근거는 같은 Git 제외 경로의 `restart-before.json`·`restart-result.json`에 보관한다.

## 연결 명부 조회 항목 축소

2026-11-12 후속 사용자 결정으로 인증 완료 회원의 `연결된 동문 명부`에서 주소(`address`)·전화(`phone`)를 제외한다. 이 두 항목은 SQL 조회·API 응답·화면 모두에서 제외하며 핸드폰(`mobile`)은 유지한다. 현재 회원 정보와 대기·거부 심사 후보의 12개 관리 항목, DB·Sheets 저장 구조·데이터는 변경하지 않는다.

제품 정책·조회 계약·운영 안내·구조 설명·미배포 변경 이력을 먼저 맞춘 뒤 공통 모듈을 재사용해 연결 명부의 10개 항목을 구현한다. 완료 조건은 Replit 개발 소스 반영과 변경 파일 lint·서식, 앱 타입·의존 경계, 영향받는 테스트 타입 및 문서 정합성 확인이다. DB 작업·운영 배포·실계정 QA는 범위에 포함하지 않는다.

연결 명부 DTO와 SELECT 필드를 10개로 제한했다. 심사 후보는 공통 10개 필드에 주소·전화를 추가해 기존 계약을 유지한다. 공통 표시 컴포넌트는 인증 완료 화면에서만 두 필드를 제외하므로 이전 응답이 브라우저 캐시에 남아 있어도 해당 항목을 표시하지 않는다.

Replit 개발 소스에 직접 반영하고 08:04 KST Node.js `20.20.0`에서 변경 코드 5개의 ESLint·Prettier, `npm run check`, `npm run check:tests`를 통과했다. 검사 전후 소스·설정·lockfile 해시가 같았다. 기존 locale 경고와 npm 업데이트 안내 외 검사 오류는 없다. 문서 정합성과 `git diff --check`도 확인했다. 실행 근거는 같은 Git 제외 경로의 `linked-fields-sync.json`·`linked-fields-checks.json`에 보관한다.

이 축소 변경의 최초 구현 시점에는 서버를 재시작하거나 실제 회원 API를 호출하지 않았다. 07:51 KST의 기동 확인을 이번 변경의 실행 검증으로 사용하지 않는다. 후속 사용자 요청으로 09:20 KST 최신 소스로 개발 앱을 다시 기동하고 공개 페이지 200·비로그인 관리자 API 401을 확인했다. 상세 근거는 [시트 컬럼 변경의 후속 재시작 기록](alumni-sheet-columns-2026-11-12.md#후속-개발-서버-재시작)에 남긴다. 실제 회원 조회·화면 동작은 미검증이며 DB 작업·운영 배포·실계정 QA·커밋·push는 수행하지 않았다.
