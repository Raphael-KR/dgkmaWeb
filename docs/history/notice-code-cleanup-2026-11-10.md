# 경조사 작성·수정 코드 정리

2026-11-10 코드 정리 요청에 따른 작업이다. [계획서의 유지보수 기준](../product/planning-proposal.md#6-기존-기능의-보완과-정리) 안에서 수행했으며 [구조 기준](../architecture/project-structure.md#개발-사본의-미커밋-변경)을 코드보다 먼저 갱신했다.

- 목표: 경조사 작성·수정의 요청 계약과 처리 순서를 읽기 쉽게 구분한다.
- 범위: AI 추출 지침·요청/응답 계약 분리, 응답 해석 함수 분리, 초안·게시·수정 라우트의 압축된 코드와 주석 정리.
- 완료 조건: 기존 공개 함수·프롬프트·모델·응답 검사·URL 우선순위·서명·권한·revision·처리 순서를 보존하고 로컬·Replit 개발 사본에 반영한다.
- 제외: 제품 정책·DB·의존성·화면 변경, 실제 외부 호출·브라우저·빌드·재시작·배포·실계정 QA·Git 게시.
- 검증: Replit의 타입·의존 경계와 변경 파일 lint, AST·문자열 대조 및 파일 기반 문서·diff 검사만 수행한다.

## 적용·검사 결과

- 문서 3개를 먼저 반영하고 경조사 코드 4개를 로컬·Replit 개발 사본에 적용했다. 추출 지침·JSON Schema·응답 형태는 `notice-extraction-contract.ts`, 요청과 응답 해석은 `notice-extraction.ts`가 담당한다. 초안·수정 라우트는 조건문·타입·호출 인수·응답 객체를 읽기 쉽게 펼쳤다.
- 시작 사본 501개와 기존 미커밋 변경을 보존했다. 계약 모듈과 이력 파일을 추가해 관리 대상은 503개다. 로컬 main `d7184ca`, Replit 개발 main `5872027`을 유지하며 변경은 미커밋 상태다.
- 2026-11-10 18:13 KST Replit에서 `npm run check`(타입·의존 경계·runtime cycle), 변경 파일 4개 ESLint, AST 보존 비교 13건, 파일 기반 문서 계약 6건과 `git diff --check`가 통과했다. 문서 83개·내부 링크 723개·앵커 260개의 정적 검사도 오류 0건이다. npm의 `C.UTF-8` locale 경고는 있었으며 검사 종료 코드는 모두 0이다.
- AST 비교는 서식·주석과 동등한 조건문 블록을 제외하고 문장·표현식·값을 대조했다. 분리한 응답 해석의 호출 지점과 본문, 추출 지침·요청 형식·필드 매핑, 공개 함수와 오류 타입을 확인했다. 지침 문자열은 변경 전과 같다. 앱을 실행하거나 OpenAI 응답을 새로 받은 검사가 아니다.
- DB·외부 API·브라우저·빌드·재시작·배포·실계정 QA·커밋·push·PR·병합은 수행하지 않았다. 실제 기능 동작 확인은 별도 실행 범위다.
