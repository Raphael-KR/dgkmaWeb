### 2차: 변경 후 소비자와 실행 범위 재대조

- 제거한 문서 검사 명령을 현재 개발 안내에서도 없앴다. history·과거 계획의 당시 검사 결과는 보존했다.
- 관리자 통계의 실제 API를 기존 권한 행렬에 포함하고, route facade 검사는 필수 등록과 의존 순서만 남겼다. 서로 독립인 도메인의 나열 순서, 제거된 메서드명, 인스턴스 속성 수는 고정하지 않는다.
- 실제 DB 8개 파일·11개 사례를 공통 opt-in 대상으로 대조했다. 명부 검사는 전체 명부를 관찰하므로 전용 DB 명령은 파일 단위 직렬 실행으로 fixture 간 간섭을 피한다. 각 사례 내부의 경쟁 요청은 그대로 병렬이며 경쟁 조건을 축소하지 않는다.
- 탈퇴 DB 검사의 기존 TEXT 본문 입력을 현행 JSONB 계약으로 변환했다. 결제 fixture가 없는데 0건을 확인하던 조회·cleanup은 제거했다. 결제 익명화 구현의 정적 확인은 유지하지만 실제 결제 행 보존은 이 테스트가 입증하지 못한다.
- 모바일 알고리즘을 과거 실측 baseline과 분리했다. 자산별 중앙값의 합과 전체 중앙값은 일반적으로 같지 않으므로 합계를 강제하던 assert도 제거했다. 실제 측정기의 baseline 형식·필수 지표 검사와 생성 경로는 유지한다.
- 검사 runner·test helper의 실제 import를 다시 확인했다. 보조 코드는 테스트 타입 검사에 남으며 앱 타입/경계 검사에서만 제외한다. 외부 Secrets·DB 선택 코드와 앱 기능은 바꾸지 않았다.

### 3차: 정적 검사 실패 원인과 혼합 파일의 범위 정리

첫 Replit 정적 확인에서 lint·서식·앱 타입/경계·테스트 타입은 통과했다. 파일 기반 20건 중 4건은 줄바꿈을 허용하지 않는 기존 문자열/정규식 때문에 실패했다. 실제 소스에서 익명 보존 안내와 lock 이후 조회·tx 갱신을 확인했으며, 실패를 숨기는 삭제 대신 공백을 허용하도록 고친다.

동일한 형태를 전수 검색해 탈퇴·명부 동기화 source assert에도 같은 문제가 있음을 확인했다. 이들 검사와 OAuth의 파일 읽기 검사는 기존 route-source 계약 파일로 모으고 이름을 security-source-contract로 명확히 한다. DB·앱 모듈을 import하는 혼합 파일을 단순 소스 점검 때문에 실행할 필요를 없앤다. DB 경쟁 검사와 OAuth hash 실행 검사는 원래 파일에 유지한다. 이름 별칭 테이블 source 검사에도 같은 줄바꿈 의존을 바로잡고, 구조 문서의 과거 “테스트 수·assertion 유지” 문장은 보호할 계약·격리 단위 유지로 정정한다.

### 4차: 개인정보 로그 검사의 오탐 정리

분리한 파일 검사와 나머지 source 검사에서 24건 중 23건이 통과했다. 남은 실패는 `error.reason`을 원문 오류로 취급한 경우다. 실제 단톡방 설정 클래스는 `missing | invalid`만 생성하며 초대 주소·Secret을 담지 않는다. 클래스와 호출 지점의 타입을 확인했다.

개인정보 로그 검사는 유지하고, 민감 필드 이름 검사를 먼저 적용한 뒤 TypeScript가 고정 문자열 값으로 확인한 속성만 허용한다. 임의 string/unknown/any·원문 오류와 회원 민감 필드 차단은 유지한다. 특정 파일/행을 예외 처리하거나 오류 로그 자체를 삭제하지 않는다. 타입 정보는 속성 값의 범위 판별에만 사용하며 타입 diagnostics를 중복 수행하지 않는다. 첫 방식은 외부 패키지까지 불러와 약 15초가 걸렸으므로 로컬 앱 소스에 한정한다. 외부·미해석 타입은 안전하다고 간주하지 않고 기존 차단 경로로 남긴다. 앱 로그·권한 코드는 변경하지 않는다.

### 5차: 통합된 의존 검사와 남은 전체 목록 대조

AST 검사로 옮긴 shared 경계의 보존 범위를 원래 검사와 대조했다. 브라우저용 shared가 shared 밖의 로컬 스크립트/설정으로 빠지는 경우도 기존과 같이 금지하고, 디렉터리 import를 실제 index 파일로 해석하도록 보완한다. 서버 전용 `shared/schema.ts` 호환 export는 예외로 유지한다. 이 변경은 기존 경계를 한 검사로 합치는 과정에서 빠질 수 있는 적용 범위를 복원하며 앱 의존성은 바꾸지 않는다.

### 6차: 전체 재순회 종료

현재 검사 목록, 실제 import/호출, npm·Replit 실행 연결, 변경 전후 보호 범위와 문서 참조를 다시 대조했다. 추가로 자율 제거·통합·축소할 항목은 0건이다. 모든 미래 변경에 불필요한 검사가 없음을 보장하는 뜻은 아니다.

테스트 파일은 55개에서 53개, 해당 파일 합계는 8,358줄에서 7,849줄로 줄었다. 2개 삭제, 1개 이름 변경·기존 사례 통합, 24개 수정, 28개 유지다. 파일 수·줄 수를 별도 목표나 통과 기준으로 사용하지 않는다. 타입/runner/공통 보조 파일과 문서 변경은 이 수치 밖이다. 파일별 판단은 `.superpowers/check-audit-20261111/inventory.json`에 기록했다.

| 파일 읽기 계약 | 9개 파일의 29개 사례 통과. 같은 소스의 통과 결과를 재사용하고 수정된 파일만 재실행 |

초기 파일 검사 실패 4건과 개인정보 로그 오탐 1건, 후속 타입 좁힘 오류 1건은 원인을 확인하고 수정한 뒤 관련 범위를 재확인했다. 실패 로그도 보존했다. 명령·시각·종료 코드·단계별 로그는 양쪽 `.superpowers/check-audit-20261111/`에 기록했다. 셸 locale 안내는 있었으나 최종 lint·타입·정적 검사의 실패는 없다.

일반 실행형 단위·HTTP·DB·모바일·브라우저·빌드·외부 수집/LLM·실계정 QA는 실행하지 않았다. 특히 결제 행을 넣지 않았던 탈퇴 DB 검사는 실제 결제 익명 보존을 입증하지 않았으며, 이번에 그 공백을 숨기는 0건 assertion을 제거했다. 나머지 실행형 검사의 이번 동작 성공도 정적 통과로 대신하지 않는다.

로컬과 Replit 개발 사본에 반영했다. commit·push·PR·병합·서버 재시작·운영 배포·DB/Secret 변경은 하지 않았다. 최종 파일 해시·Git 상태·문서 상대 링크와 `git diff --check` 결과는 `completion.json`에 기록한다.

## 사용자 결정 필요 항목

없음. 보안·권한·저장 호환·현행 회비 판정·성능 임계값을 바꾸지 않고 정리할 수 있었다. 미실행 DB·브라우저 검사는 별도 실행 권한을 유지하며, 이번 정리의 완료를 위해 추가 승인을 요구하지 않는다.
