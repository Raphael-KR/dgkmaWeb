# 개발 기본명부 전환

2026-11-21 Replit 개발 DB `heliumdb`에서 [별칭 소유자 전환 SQL](../../scripts/link-roster-aliases-development.sql)을 적용했다. 기존 동문 연결을 따라 소유자 키를 UUID로 바꾸고 동일 별칭 중복 방지와 대표 이름 최대 1개 제약을 유지했다. 실행 전 별칭과 가입 심사 기록은 각각 0건이었다.

새 읽기 전용 연결에서 동문 3,458명, 승인 계정 1개, 미가입 동문 3,457명, 별칭 0건, 가입 심사 기록 0건을 확인했다. 옛 명부 3,458행도 남아 있다. 개발 catalog에서 새 FK와 두 고유 인덱스를 확인했다. SHA-256은 `914555133faa7530e8684b2d0540f7ada53d67f8c17010a2aeaf7c7dba91ada0`이다.

개발 소스의 가입·심사·탈퇴·경조사·명부·통계는 users를 사용한다. 회원 명부 응답에서 UUID와 명부 휴대전화·메모를 제외했다. 새 기수와 기존 동문 정정은 [관리자 SQL 절차](../runbooks/database-operations.md#동문-기본명부-관리)에 따른다. 시트 재수입이나 운영 전환은 실행하지 않았다. 실제 별칭이 있는 데이터로 이관하거나 가입 상태를 바꾸는 시험은 하지 않았다.

Replit 개발 작업공간에서 앱 타입·브라우저/서버 경계(278개 파일), 테스트 코드 타입, 변경 파일 ESLint·Prettier와 git diff --check를 통과했다. Drizzle의 생성 SQL에서도 대표 이름, 별칭 목록, 이름 대조 조건 세 곳이 모두 외부 users 행의 UUID를 가리키는지 확인했다. 생성 SQL은 DB에서 실행하지 않았다.

## 회비 원장 대조 후 개발 명부 증분

대학원 동문 3명을 시트 UUID로 신규 등록하고 기존 동문 1명의 공식 이름·개명 메모를 정정했다. 같은 UUID에 대표 이름과 옛 이름 별칭을 보존했다. 신규 3명의 기수·입학일·졸업일은 원본대로 비웠고 가입 상태는 미가입이다.

별도 읽기 전용 연결에서 명부가 3,458명에서 3,461명으로 늘었고 신규 3명의 명부 정보와 개명 별칭이 일치함을 확인했다. 승인 계정과 카카오 연결 계정은 각각 1개였다. 다른 기존 동문 2명도 시트와 UUID·성명·기수·휴대전화가 일치했다. 이 두 명의 2026년 귀속 납부는 사무국 원장에서 12건 72,000원으로 대조했다. 개발 DB의 완료 납부는 0건이다. 실제 입금일·원거래 연결은 [회비 DB 변경안](../product/annual-dues-database-design.md)의 개발 적용 대상이다.
