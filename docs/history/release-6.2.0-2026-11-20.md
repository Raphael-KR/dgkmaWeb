# 6.2.0 릴리스

버전은 6.1.0에서 MINOR를 올린다. 명부 사전 등록·게시판 이어보기·역사관 자료가 추가됐고, 앱과 서버를 함께 갱신하는 내부 회원 키를 UUID로 전환한다. 다음카페 게시글·첨부·회원 사진첩의 운영 이전은 개발 완료본을 사용한다.

## 후보 검증

Replit 개발 워크스페이스에서 Node 20.20.0과 npm 10.8.2로 검사했다. 소스 후보 `5f03237`과 Replit 개발 이력을 포함한 `96b0c99`의 tree가 같다. `npm run lint`, 변경 JS·TS·CSS의 Prettier 검사, `npm run check`(의존 경계 포함), `npm run check:tests`, 역사관 공개 자료 검사와 `npm run build`가 통과했다. 격리 작업 트리의 최초 빌드에서 로고를 찾지 못해 실제 Replit 앱이 사용하는 자산을 연결하고 다시 빌드했다.

일반 회귀는 DB 쓰기 검사를 끈 상태에서 255건 중 244건 통과·11건 건너뜀·실패 0건이다. 첫 실행이 발견한 UUID 세션 기대값, Sheets 장애 테스트의 실제 DB 의존, 시차 없는 부고 발인 시간의 해석을 수정했다. 서식과 lint의 Node 환경 지정 외에 해당 검사 입력은 동일하다. DB fixture 생성·실계정 로그인·회원 화면 클릭은 실행하지 않았다.

기존 숫자 회원 키의 일반 응답·소유권 비교를 제거하고 서버가 본인 여부를 제공한다. 운영 전환에는 기존 회원 외래키와 카카오 연결을 대조하는 경로, 구 명부용 미리보기 및 가입 심사·계정 권한 검사를 유지했다. 검사 삭제는 없다. Git에는 이관 도구와 승인된 공개 역사관 자료를 포함하며 비공개 명부·회원 사진·콘텐츠 묶음은 제외했다.

## 운영 전환 전 확인

운영 neondb는 정수 회원 1명·명부 3,458건·게시글 6건·댓글 1건·납부 0건이었다. 전환 미리보기에서 개발 UUID 3,458건과 운영 명부 전부, 기존 계정 1건이 일대일 대응했다. 사용자가 개발과 운영의 Storage 루트가 동일함을 확인했다. 앨범은 환경별 카탈로그를 사용한다.

## 운영 회원 전환

neondb에서 회원 키와 다섯 외래키를 UUID로 전환했다. 새 연결로 확인한 회원 3,458명 모두 개발의 고정 UUID와 일치했고, 3,457명은 로그인 정보·승인·관리자 권한이 없는 사전 등록 행이었다. 기존 승인 관리자 1명의 연결을 보존했다. metadata-only catalog 완료 표식과 운영 스키마 구조를 확인했다. 별도 백업과 Secrets 변경은 없었다.

## 게시 및 비로그인 확인

[PR #42](https://github.com/Raphael-KR/dgkmaWeb/pull/42) 병합 커밋 `983ca657aa48730590eb2af373513d4ed630def6`, tree `22b781f59f37cc3c366b9b70c8564b9132cc2ad9`를 배포했다. Replit에서 기존 deployment ID `eb4a4e6a-1633-4882-8ee8-c1e1b9313e8b`의 pending·building·running·promoting·success를 확인했다. 게시 커밋 `f62fa32`의 tree가 일치한다.

공개 페이지 7개의 canonical, 사진첩 noindex와 사이트맵 제외, 회원 게시글·사진첩·회비·관리자 API의 비로그인 401을 확인했다. 운영 HTML이 참조하는 진입 자산과 후보 정적 자산 69개의 SHA-256이 일치했다. 태그 `v6.2.0`은 실제 배포 후보를 가리킨다.

## 다음카페 운영 이전

개발 완료본 지문은 `3de88a4e2b281a7de4ed97b934a57a9c8418b90e1a1239f9d24a5eab1832aed4`이다. 운영의 기존 글 6건·댓글 1건을 교체했다. 새 연결에서 글 80건과 출처 80건·댓글 0건을 확인하고 전체 본문·작성자·날짜·분류·첨부 참조를 개발 묶음과 대조했다. 운영 카탈로그 52개 앨범·사진 항목 406개도 대조했다. 고유 사진 403개와 글 첨부 11개의 바이트 해시가 일치했다.

첫 복사는 263개 확인 후 유휴 DB 연결이 종료되어 게시글 커밋 전에 중단됐다. 파일 작업 중 DB 연결을 닫고 쓰기 직전에 다시 열도록 이전 CLI를 수정했다. 다음 시도에서 일반글의 SQL NULL을 JSON null로 직렬화해 경조사 CHECK가 쓰기를 거부했다. 트랜잭션 롤백 후 기존 글·댓글 수를 확인하고 SQL NULL을 보존해 같은 묶음으로 완료했다. 후속 CLI는 앱 번들에서 호출되지 않는다. Replit에서 Node 구문·ESLint·Prettier와 실제 이전·새 연결 대조를 확인했다.

원본 170건의 운영 대응표는 게시글 80건·사진첩 52건·공개 역사관 자료 36건 반영 및 정책상 제외 2건이다. 개발 UUID·다음카페 원본이나 게시글 묶음을 Git에 저장하지 않았다. 로컬 이전 영수증은 Git 제외 `local-backups/community/migration/production-6.2.0/receipt.json`에 보존한다. 밴드 자료는 포함하지 않았다.
