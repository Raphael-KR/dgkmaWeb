# 6.2.0 릴리스

버전은 6.1.0에서 MINOR를 올린다. 명부 사전 등록·게시판 이어보기·역사관 자료가 추가됐고, 앱과 서버를 함께 갱신하는 내부 회원 키를 UUID로 전환한다. 다음카페 게시글·첨부·회원 사진첩의 운영 이전은 개발 완료본을 사용한다.

## 후보 검증

Replit 개발 워크스페이스에서 Node 20.20.0과 npm 10.8.2로 검사했다. 소스 후보 `5f03237`과 Replit 개발 이력을 포함한 `96b0c99`의 tree가 같다. `npm run lint`, 변경 JS·TS·CSS의 Prettier 검사, `npm run check`(의존 경계 포함), `npm run check:tests`, 역사관 공개 자료 검사와 `npm run build`가 통과했다. 격리 작업 트리의 최초 빌드에서 로고를 찾지 못해 실제 Replit 앱이 사용하는 자산을 연결하고 다시 빌드했다.

일반 회귀는 DB 쓰기 검사를 끈 상태에서 255건 중 244건 통과·11건 건너뜀·실패 0건이다. 첫 실행이 발견한 UUID 세션 기대값, Sheets 장애 테스트의 실제 DB 의존, 시차 없는 부고 발인 시간의 해석을 수정했다. 서식과 lint의 Node 환경 지정 외에 해당 검사 입력은 동일하다. DB fixture 생성·실계정 로그인·회원 화면 클릭은 실행하지 않았다.

기존 숫자 회원 키의 일반 응답·소유권 비교를 제거하고 서버가 본인 여부를 제공한다. 운영 전환에는 기존 회원 외래키와 카카오 연결을 대조하는 경로, 구 명부용 미리보기 및 가입 심사·계정 권한 검사를 유지했다. 검사 삭제는 없다. Git에는 이관 도구와 승인된 공개 역사관 자료를 포함하며 비공개 명부·회원 사진·콘텐츠 묶음은 제외했다.

## 운영 전환 전 확인

운영 neondb는 정수 회원 1명·명부 3,458건·게시글 6건·댓글 1건·납부 0건이었다. 전환 미리보기에서 개발 UUID 3,458건과 운영 명부 전부, 기존 계정 1건이 일대일 대응했다. 사용자가 개발과 운영의 Storage 루트가 동일함을 확인했다. 앨범은 환경별 카탈로그를 사용한다.
