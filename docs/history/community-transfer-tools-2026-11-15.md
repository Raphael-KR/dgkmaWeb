# 백업 이관·개발 완료본 운영 이전 도구 — 2026-11-15

## 확정 흐름과 구현

백업→개발 이관과 개발 완료본→운영 이전을 분리했다. 중간에 검토했던 백업→운영 직접 입력 경로는 최종 도구에서 허용하지 않는다. 기준은 [이관 기준](../product/community-archive-migration-proposal.md), 호출·환경·부수 효과는 [실행 런북](../runbooks/community-migration.md)을 따른다.

Git 제외된 local-backups/community/tools의 apply-post-migration.mjs·apply-heritage-albums.mjs는 development만 허용한다. 게시글의 명시적 전체 리셋과 일회성 삽입, 사진첩 전체 카탈로그 교체를 지원하고 반복 증분·앨범별 병합은 하지 않는다. 환경 선택은 migration-target.mjs로 분리했다. 개발 기록 도구 두 개는 명시적 영수증과 환경을 검사하며 실제 기록은 실행하지 않았다.

promote-community-content.mjs를 추가했다. 개발 DB의 이관 발행 글(가린 글 포함)과 연결 첨부·전체 사진첩·사진을 별도 development-content.json/blobs 묶음으로 내보내고 그 묶음만 운영에 이전한다. 계정·명부·회비·세션·일반 테스트 글·초안·댓글은 이전하지 않는다. 이관 글에 회원 연결이 있으면 임의 매핑하지 않는다. 글 ID·본문·메타데이터·상태·시각·버전·앱 내부 첨부 경로·앨범 ID를 유지하고 카테고리는 이름으로 대응한다. 운영의 스키마와 카테고리를 먼저 확인하며 DB/파일 검증 결과와 원천/개발/운영 ID는 스냅샷 해시에 연결한 영수증으로 기록한다.

운영 posts 전체 리셋은 별도 모드에서만 수행하도록 구현했다. 파일 물리 삭제·일반 회원 데이터 복사·스키마 변경·자동 배포는 없다. 파일 복사·DB 커밋·카탈로그 교체는 원자적 작업이 아니므로 실패 단계와 완료된 단계를 구분하며 자동 삭제나 커밋 후 원복을 하지 않는다. 공개 역사관 JSON·문서·사진은 기존 코드 릴리스로 반영한다.

## 검사와 미실행

2026-11-15 Replit 개발 환경에 개인정보 없는 도구 소스만 반영해 JavaScript 4개 node --check·공식 Prettier·ESLint, Python 2개 AST 구문 검사를 통과했다. 최종 서식 정리본을 로컬 도구에 반영했다. 변경 문서의 상대 파일 링크·기준 간 정합성과 git diff --check도 통과했다. 앱 코드·타입 변경이 없어 전체 앱 타입 검사·빌드·회귀를 추가하지 않았다.

도구를 실제 실행하지 않았다. 내보내기·검증 모드·DB/Storage 읽기·Secret 추가·DB 리셋·이관·파일 복사·운영 배포·실계정 QA·SQLite 쓰기·Git 게시 모두 미실행이다. 운영 데이터 일치·장애 시 부분 반영 처리·화면 표시·SQL 실행 성공은 미검증이며 정적 검사 결과로 대신하지 않는다. 원본 백업·기존 개발 payload·영수증은 보존했다.
