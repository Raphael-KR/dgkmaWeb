## 문서·코드 재검토

- 목적별 정본과 과거 계획·운영 이력의 구분은 유지된다. [이력 색인](README.md)에 직전 게시글·편집기·경조사·수집기 책임 분리 연결이 빠져 있어 추가했다.
- [편집기 참조](../reference/post-editor.md)에 현재 내부 파일 소유 위치가 없어 추가하고 미커밋 개발 사본과 공식 구현·운영 적용을 구분했다.
- `replit.md`의 “이번 문서 작업”을 날짜가 있는 릴리스 이력과 후속 개발 사본으로 명확히 구분했다. 운영 상태를 새로 확인한 것으로 쓰지 않았다.
- 앱 TS/TSX/CSS 205개(생성 UI·테스트·복사한 Python 작성기 제외)의 최대 파일은 `public-page-fetcher.ts` 399줄이며 500줄 초과는 없다. 공개 홈 398줄은 정적 섹션, DB 스키마 321줄은 정의 중심이다. 회원 홈 312줄·프로필 309줄은 화면 조립 비중이 크며 줄 수만을 이유로 추가 분리하지 않았다.
- 기존 인증·명부·관리자 및 네 영역의 분리 구조를 유지했다. 확인한 앱 주석에서 예전 Supabase 로그인·Task TODO 같은 잔재는 찾지 못했다. 업로드의 긴 예시 주석은 현재 두 호출 경로와 오류 처리 차이를 설명하도록 줄였다.
