# 개발 운영 문서 정리 설계

## 목적

현재 코드와 프로덕션 운영 상태를 기준으로 개발 문서를 현행화한다. 장기 비전, 실제 구현 상태, 운영 절차, 검증 절차, 변경 이력의 책임을 파일별로 분리해 오래된 설명이 이후 개발과 배포를 잘못 이끌지 않게 한다.

## 기준 정보

문서 내용이 충돌할 때 다음 순서로 사실을 확인한다.

1. 현재 프로덕션에서 검증된 동작
2. `main` 브랜치의 코드와 Replit 설정
3. `AGENTS.md`의 현재 작업 규칙
4. 기존 운영 문서
5. 과거 기획과 변경 이력

과거 기록은 당시 사실로 보존하되, 현재 상태처럼 읽힐 수 있는 표현은 최신 문서에서 명확히 구분한다.

## 범위

### `README.md`

프로젝트의 문서 진입점으로 확장한다.

- 프로젝트 목적과 현재 운영 주소
- 현재 기술 스택의 짧은 요약
- 개발, 검증, GitHub 동기화, Replit 재배포의 기본 흐름
- 개발 운영 문서 목록과 각 문서의 역할
- `planning_proposal.md`, `roadmap.md`, `walkthrough.md`, `CHANGELOG.md`, `replit.md`, `AGENTS.md` 링크

비밀값, 데이터베이스 접속 문자열, SSH 개인키 정보는 기록하지 않는다.

### `planning_proposal.md`

Ver 3.0의 장기 비전과 제품 정책 문서로 유지한다.

- 각 주요 기능을 구현 완료, 부분 구현, 미구현으로 표시
- 가입 불일치 처리, 게시판 분류, 부고 공개 범위처럼 아직 확정되지 않은 정책을 별도 표시
- 현재 정규식 기반 부고 파싱과 향후 AI 기능을 구분
- 현재 내부 납부 기록과 향후 실제 결제 연동을 구분
- 실행 순서와 세부 완료 조건은 `roadmap.md`로 연결

### `roadmap.md`

현재 시점의 실행 계획을 새로 만든다.

- `긴급`: 관리자 API, 결제 기록 API, 개인정보 접근 제어
- `다음`: 가입 정책 확정, 게시판 분류 확정, PostgreSQL 기준 명부 일원화, 운영 절차 정비
- `이후`: 알림톡과 SMS, 실제 결제, 화환 주문, 장학사업, 분석
- 각 과제에 상태, 목적, 완료 조건, 선행 조건을 기록
- 구현되지 않은 외부 연동을 완료된 기능처럼 표현하지 않음

### `walkthrough.md`

현재 프로덕션의 기능 검증 체크리스트로 재작성한다.

- 실제 공개 및 회원 전용 경로
- 카카오 로그인과 명부 일치/불일치 흐름
- 게시판 카테고리, 글, 댓글, 이미지 첨부 검증
- 주소록의 기수 및 지역 제한 검증
- 부고 목록, 작성, 정규식 기반 문자 파싱, 상세 검증
- 프로필과 권리회원 표시 검증
- 관리자 기능은 서버 권한 보완이 끝날 때까지 주의 상태로 표시
- `npm run check`, `npm run build`, 배포 후 핵심 API 점검 포함

### `replit.md`

현재 Replit 운영 구조만 설명하도록 재작성한다.

- GitHub `main`, 로컬, Replit 개발 워크스페이스의 관계
- Replit 개발 DB와 배포 프로덕션 DB가 분리되어 있음을 명시
- SSH는 개발 워크스페이스 접속이며 프로덕션 실행 환경 접속이 아님을 명시
- 현재 카카오 REST OAuth와 프로덕션 redirect URI
- 필요한 환경변수 이름만 기록
- Replit에서 `npm run check`, `npm run build`, Republish하는 절차
- 스키마 변경과 운영 데이터 seed를 구분
- Supabase, 카카오 JavaScript SDK, 과거 임시 도메인 설명 제거

### `CHANGELOG.md`

과거 버전 기록을 보존하고 최신 변경을 `Unreleased`에 추가한다.

- 카카오 REST OAuth v5 및 세션 안정화
- 활동 지역 온보딩과 주소록 제한
- 권리회원 상태 표시
- 게시판 댓글과 이미지 첨부
- 부고 상세
- 카테고리 생성 권한 및 이미지 업로드 보안

과거 기록의 표현이 현재 구조와 달라도 삭제하지 않고, 현재 상태는 새 항목과 운영 문서에서 설명한다.

### `AGENTS.md`

`AGENTS.md`를 AI 작업 규칙의 유일한 기준 문서로 Git에 추가한다. 기존 `CLAUDE.md`와 `AGENTS.md`는 제목과 도구명 외의 규칙이 동일하므로 별도 병합 작업 없이 `AGENTS.md`의 내용을 기준으로 유지하고 `CLAUDE.md`를 삭제한다. `README.md`와 다른 문서에서는 `AGENTS.md`만 안내하며 `CLAUDE.md` 참조를 남기지 않는다.

## 제외 범위

- 애플리케이션 소스 코드 변경
- 데이터베이스 스키마 또는 운영 데이터 변경
- `CLAUDE.md` 외 기존 문서 파일의 이동이나 삭제
- 외부 서비스 설정 변경
- 보안 문제의 실제 코드 수정

## 작성 원칙

- 현재 구현과 향후 목표를 한 문장에서 섞지 않는다.
- 검증되지 않은 기능에 `완료`, `정상`, `연동됨` 표현을 사용하지 않는다.
- 환경변수는 이름만 쓰고 값은 쓰지 않는다.
- 운영 명령은 Replit 개발 워크스페이스와 프로덕션 SQL 콘솔의 실행 위치를 구분한다.
- 같은 설명을 여러 문서에 복제하지 않고 기준 문서로 링크한다.
- 한국어를 기본으로 하며 명령어, 경로, API 이름은 원문 표기를 유지한다.

## 검증

문서 수정 후 다음을 확인한다.

1. 모든 내부 Markdown 링크가 존재하는 파일을 가리키는지 확인
2. `Supabase`, `Kakao JavaScript SDK`, 과거 Replit 개발 도메인이 현재 구성 설명에 남아 있지 않은지 확인
3. `walkthrough.md`의 경로와 API가 현재 코드에 존재하는지 대조
4. `roadmap.md`의 완료 항목이 실제 프로덕션 검증 결과와 일치하는지 확인
5. 환경변수 값, 토큰, 데이터베이스 URL, 개인키가 문서에 포함되지 않았는지 확인
6. `CLAUDE.md` 파일과 해당 파일을 가리키는 참조가 남아 있지 않은지 확인
7. `git diff --check`로 Markdown 형식 오류 확인

애플리케이션 코드를 변경하지 않으므로 `npm run check`와 `npm run build`는 이번 문서 작업의 필수 검증에서 제외한다.

## 완료 조건

- `README.md`에서 모든 개발 운영 문서를 찾을 수 있다.
- 장기 비전은 `planning_proposal.md`, 실행 순서는 `roadmap.md`, 실제 검증은 `walkthrough.md`에서 각각 확인할 수 있다.
- `replit.md`가 현재 GitHub, Replit 개발, Replit 프로덕션의 관계를 정확히 설명한다.
- `CHANGELOG.md`에 최근 배포 변경이 기록된다.
- `AGENTS.md`가 유일한 AI 작업 규칙 문서로 추적되고 `CLAUDE.md`와 관련 참조가 제거된다.
- 현재 기능과 향후 계획을 혼동하게 만드는 핵심 표현이 제거된다.
- 소스 코드와 사용자 자료 파일에는 변경이 없다.
