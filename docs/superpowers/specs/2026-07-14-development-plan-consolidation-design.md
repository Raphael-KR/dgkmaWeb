# 개발계획 문서 통합 설계

## 목표

`planning_proposal.md`와 `roadmap.md`에 중복된 기능 상태와 우선순위를 하나의 현재 기준 문서로 통합한다. 실제 코드, Replit 검증, 프로덕션 검증, 승인된 운영 정책을 반영하고 과거 방향과 현재 계획을 구분한다.

## 결정

- `planning_proposal.md`를 제품 비전, 확정 정책, 현재 상태, 개발 순서와 완료 조건을 모두 담는 단일 기준 문서로 사용한다.
- `roadmap.md`는 과거 링크를 깨뜨리지 않는 짧은 이전 안내문으로 남긴다. 기능 상태나 계획을 중복 기록하지 않는다.
- `walkthrough.md`는 수동 회귀 검증 절차로 유지한다.
- `CHANGELOG.md`는 당시 변경 이력을 보존하며 현재 계획의 기준으로 사용하지 않는다.
- 과거 `docs/superpowers/specs`와 `docs/superpowers/plans`는 당시 승인·구현 맥락을 보존한다. 현재 상태와 충돌하면 통합 개발계획을 우선한다.

## 사실 확인 우선순위

1. 실제 프로덕션에서 확인한 결과
2. 현재 `main` 코드와 Replit 개발 환경의 자동화·수동 검증
3. 사용자가 승인한 최신 제품·운영 정책
4. `walkthrough.md`, `replit.md`, DB 운영 런북과 현재 설정
5. 변경 이력과 과거 설계·계획 문서

## 통합 문서 구조

1. 문서 역할과 사실 확인 기준
2. 제품 목표와 설계 원칙
3. 상태·우선순위 정의
4. 확정된 운영 정책
5. 현재 검증 완료 기반
6. P0/P1 보안·무결성 과제
7. 현재 진행 중인 개발과 완료 조건
8. 다음 개발 목표
9. 장기·보류 과제
10. 변경되거나 폐기된 방향
11. 기술·개발·배포 원칙

모든 현재 과제는 하나의 표에만 상태를 기록한다. 기능 설명에서 상태를 반복하지 않고 현재 표를 참조한다.

## 상태 체계

- `기능 검증 완료`: 핵심 사용자 흐름을 프로덕션에서 확인했다.
- `진행 중`: 코드, 데이터, 배포 또는 실제 사용자 검증 중 하나 이상이 남았다.
- `진행 예정`: 다음 개발 대상으로 확정됐지만 구현을 시작하지 않았다.
- `정책 결정 필요`: 구현 전에 운영 결정을 내려야 한다.
- `보류`: 명시된 선행 조건 이후 진행한다.
- `방향 변경`: 과거 계획이지만 현재 구현·운영 방향에서는 채택하지 않는다.

## 반영할 주요 실제 상태

- 카카오 REST OAuth, 환경별 앱 분리, 최소 동의항목, PostgreSQL 명부 매칭, 탈퇴와 연결 해제는 프로덕션 검증 완료다.
- Google Sheets는 현재 명부 관리 원본이고 PostgreSQL `alumni_database`는 로그인 런타임 복제본이다.
- 게시판, 댓글, 이미지 첨부, 동문 주소록, 권리회원 표시와 레거시 부고 기본 기능은 검증 완료 기반이다.
- 경조사 통합 모델·API·등록·초안 UI는 코드와 Replit 검증 및 배포 경로가 존재하지만 데이터 마이그레이션과 실제 회원 데스크톱·모바일 검증이 남았다.
- URL 본문 수집은 구현하지 않았으며 현재 입력 문자만 분석하고 준비 중 안내를 표시한다.
- 관리자 API, 결제 기록, 개인정보 로그와 경조사 접근 정책은 보호 코드가 있으나 역할별 프로덕션 검증을 완료 조건으로 유지한다.

## 변경·폐기 기록

다음 항목은 현재 계획에서 제외하거나 바뀐 방향으로 명시한다.

- Supabase 클라이언트 로그인과 Google SSO 관리자 인증
- 카카오 JavaScript SDK·카카오싱크 및 CI 수집
- 개발·운영 공용 카카오 앱과 일반 Kakao Secret
- 부고 데이터 API 공개 운영
- Google Sheets를 즉시 폐기하고 PostgreSQL로 곧바로 전환하는 방식
- 별도 부고 등록 메뉴와 `/o` 목록 중심 UX
- 검증되지 않은 외부 URL의 무제한 수집 또는 생성형 AI 추론
- 월별 납부 상태를 권리회원 기준으로 삼는 정책

알리고와 카카오페이는 확정 공급자가 아니라 향후 메시지·결제 구현 시 비교할 후보로 기록한다.

## 참조 정리

- `README.md`, `replit.md`, `walkthrough.md`는 현재 계획 링크를 `planning_proposal.md` 하나로 통일한다.
- `roadmap.md`는 `planning_proposal.md`와 `walkthrough.md` 링크만 제공한다.
- 역사 문서의 기존 `roadmap.md` 링크는 안내문이 연결을 보존하므로 일괄 수정하지 않는다.

## 검증

- 통합 문서에 현재 카카오, 명부, 경조사와 보안 상태가 존재한다.
- 통합 문서에 방향 변경 항목이 존재하고 현재 계획과 혼동되지 않는다.
- `roadmap.md`에 독립적인 상태표나 우선순위가 남지 않는다.
- 저장소의 Markdown 상대 링크가 모두 존재한다.
- 문서 계약 테스트, 타입 검사와 빌드가 통과한다.
