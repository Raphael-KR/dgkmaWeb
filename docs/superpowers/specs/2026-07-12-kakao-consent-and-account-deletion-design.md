# 카카오 동의항목 심사 및 회원 탈퇴 설계

## 목표

카카오 로그인에서 실제 사용하는 개인정보만 요청하고, 서비스 화면·개인정보 처리방침·카카오 심사 자료가 동일한 수집 범위와 목적을 설명하도록 정비한다. 회원이 서비스 안에서 직접 탈퇴하면 카카오 연결 해제와 로컬 개인정보 삭제가 함께 완료되는 흐름을 제공한다.

## 적용 범위

- 카카오 OAuth 동의항목 최소화
- 로그인 화면의 수집항목 및 목적 안내
- 프로필 사진의 실제 사용
- 이용약관과 개인정보 처리방침의 실제 구현 정합성 확보
- 카카오 연결 해제를 포함한 회원 탈퇴 API와 사용자 화면
- 자동화 테스트, Replit 개발 서버 검증, 카카오 심사용 PDF

개인정보 국외이전 정보 등록은 실제 이전받는 업체·국가·연락처를 확인한 뒤 별도 작업으로 처리한다. 확인되지 않은 업체명이나 이전 조건은 이번 문서와 개인정보 처리방침에 추정하여 기재하지 않는다.

## 개인정보 최소화 정책

### 카카오에서 수집하는 항목

| 항목 | 조건 | 사용 목적 | 실제 사용 위치 |
| --- | --- | --- | --- |
| 이름 | 필수 | 졸업생 명부 대조와 동문 자격 확인 | 가입 처리, 내 정보 |
| 카카오계정 이메일 | 필수 | 회원 식별, 계정 관리, 동문회 공식 안내 | 가입 처리, 내 정보 |
| 카카오계정 전화번호 | 필수 | 졸업생 명부 대조와 동문 자격 확인 | 가입 처리, 내 정보 |
| 프로필 사진 | 선택 | 회원 프로필 표시 | 내 정보 |
| 생일·생일 유형·윤달 여부 | 선택 | 회원 맞춤형 생일 축하 화면 제공 | 내 정보, 생일 당일 축하 배너 |

카카오 회원번호는 로그인 연결과 계정 식별을 위해 서버에서 처리한다. 카카오 닉네임은 요청하거나 회원 이름의 대체값으로 사용하지 않는다.

### 이번 심사에서 제외하는 항목

- CI(연계정보)
- 성별, 연령대, 출생 연도
- 친구 목록, 카카오톡 채널 추가 상태, 접근권한

CI는 카카오의 제휴형 회원 비교식별 정보이며 본인인증 수단이 아니다. 단일 카카오 앱인 현재 서비스에서는 카카오 회원번호, 이메일, 정규화 전화번호, PostgreSQL 동문 명부의 단일 회원 연결로 중복가입을 막고 CI를 수집하지 않는다. 여러 앱이나 서비스 사이의 동일인 비교가 실제로 필요해질 때 별도 제휴와 개인정보 영향 검토 후 다시 판단한다.

## 로그인 화면

`/login` 첫 화면에서 서비스명, 카카오 로그인 버튼, 필수·선택 수집항목과 목적을 함께 노출한다.

- 필수: 이름, 이메일, 전화번호
- 선택: 프로필 사진, 생일
- 프로필 사진에 동의하지 않아도 가입할 수 있음을 명시한다.
- 생일에 동의하지 않아도 가입할 수 있으며 생일 축하 화면만 제공되지 않음을 명시한다.
- `카카오싱크 간편가입` 표현을 제거하고 현재 구현과 일치하는 `카카오 로그인`으로 표기한다.
- 서비스 이용약관과 개인정보 처리방침 링크를 유지한다.
- 카카오 로그인 뒤 활동 지역을 별도로 입력한다는 점은 카카오 제공항목과 구분한다.

설명은 심사용 정보 제공에 집중하며 과도한 마케팅 문구나 중첩된 카드 구조를 추가하지 않는다.

## 프로필 사진 사용

사용자가 프로필 사진 제공에 동의했고 값이 존재하면 내 정보 화면의 프로필 이미지로 표시한다. 값이 없거나 이미지 로딩에 실패하면 현재의 이름 첫 글자 표시로 대체한다. 외부 이미지 URL은 저장된 원본 HTTPS URL을 사용하며 임의로 변형하지 않는다.

## 생일 축하 MVP

생일 정보는 선택 동의이며 로그인한 본인에게만 사용한다.

- 내 정보에 저장된 생일과 양력·음력·윤달 구분을 표시한다.
- 오늘이 사용자의 생일이면 홈과 내 정보 중 최소 한 곳에 본인 전용 축하 배너를 표시한다.
- 공개 생일 목록, 다른 회원의 생일 조회, 쿠폰, 카카오 메시지 발송은 이번 범위에서 제공하지 않는다.
- 음력 생일은 한국천문연구원 기준의 `korean-lunar-calendar` 라이브러리로 해당 연도의 양력 날짜를 계산한다.
- 선택 동의를 철회해 카카오 사용자 정보 응답에 생일이 없으면 다음 로그인에서 저장된 생일·유형·윤달 값을 모두 `NULL`로 갱신한다.
- 생일 판단 로직은 한국 시간대의 오늘 날짜를 사용하고 양력, 음력, 윤달, 연말·연초 사례를 자동화 테스트로 검증한다.

## 약관 및 개인정보 처리방침

### 제거하거나 수정할 내용

- CI 추가 수집 예정 문구 삭제
- 구현되지 않은 생일 축하 쿠폰·카카오 메시지 문구를 본인 전용 인앱 생일 축하 화면으로 수정
- 실제로 수집하지 않는 근무지 정보 삭제
- 카카오싱크 또는 간편가입으로 오인할 수 있는 표현을 카카오 로그인으로 수정
- 구현되지 않은 메시지 발송을 현재 제공 기능처럼 단정하지 않음

### 개인정보 처리방침에 명시할 내용

- 개인정보 처리 목적
- 수집 출처와 항목
- 필수·선택 조건
- 회원 탈퇴와 보유기간
- 작성 콘텐츠와 결제 기록의 탈퇴 후 처리
- 회원이 서비스 안에서 탈퇴하는 경로

회원 개인정보는 탈퇴 시 삭제한다. 게시글·댓글·발행된 경조사는 서비스 기록의 연속성을 위해 작성자 연결만 제거하고 콘텐츠는 유지한다. 미발행 경조사 초안은 삭제한다. 결제 기록은 법령상 또는 회계상 필요한 기간 동안 보존할 수 있도록 사용자 연결을 제거하고 기록 자체는 유지한다.

## 서버 소유 카카오 로그인

카카오 인가 코드는 브라우저가 서버에 한 번 전달한다. 서버는 토큰 교환, 카카오 사용자 정보 조회, 기존 회원 확인, 동문 명부 매칭, 회원 생성 또는 갱신, 세션 저장을 한 요청 안에서 완료한다.

- 액세스 토큰, 카카오 원본 사용자 응답, 카카오 오류 원문을 브라우저에 반환하지 않는다.
- 브라우저가 카카오 개인정보를 받아 다시 `/api/auth/kakao`로 보내는 현재 왕복 구조를 제거한다.
- 성공 응답은 로그인 결과와 클라이언트 화면에 필요한 최소 회원정보만 포함한다.
- 최소 회원정보에는 이름·이메일·전화번호·프로필 사진·활동지역·회원상태와 선택 동의한 생일 표시 정보가 포함될 수 있다. 알림 기능이 구현되지 않은 동안 `kakaoSyncEnabled`는 클라이언트 응답과 프로필 수정 입력에 포함하지 않는다.
- DB 호환을 위해 남아 있는 미사용 개인정보 컬럼은 공통 직렬화 함수의 허용 목록 밖이면 클라이언트에 전달하지 않는다.
- 실패 응답은 안전한 서비스 오류 코드와 사용자 안내만 포함한다.

여기서 “브라우저 개인정보 비노출”은 로그인한 본인의 서비스 화면에 필요한 최소 회원정보 표시를 금지한다는 뜻이 아니다. 금지 대상은 카카오 원본 응답, 토큰, 어드민 키, 오류 원문, 불필요한 개인정보 왕복과 화면에 사용하지 않는 필드다.

## 중복가입 방지

회원 생성 전 다음 식별 계층을 순서대로 적용한다.

1. 카카오 회원번호의 기존 `UNIQUE` 제약
2. 이메일의 기존 `UNIQUE` 제약
3. 카카오 전화번호를 비교용 숫자 문자열로 단방향 정규화한 기존 회원 조회
4. PostgreSQL `alumni_database.mobile`과 이름 일치 및 해당 동문 행의 단일 `matched_user_id` 연결

전화번호와 이름이 일치하는 동문 행이 이미 다른 회원에게 연결돼 있거나 같은 정규화 전화번호의 회원이 존재하면 새 사용자를 만들지 않고 기존 계정 안내 또는 관리자 확인 상태로 처리한다. 로그인 매칭은 Google Sheets를 조회하지 않고 1회 이관된 PostgreSQL 동문 명부를 원본으로 사용한다. 원본 카카오 전화번호와 동문 명부 전화번호는 저장 시 임의 변경하지 않고 비교할 때만 정규화한다.

가입대기 생성·갱신과 관리자 승인은 카카오 회원번호와 소문자 이메일 identity advisory lock을 공유한다. 가입대기 저장소는 lock 획득 직후 같은 카카오 회원번호의 `users` 행을 다시 조회한다. 승인이 먼저 완료됐다면 새 pending을 만들지 않고 `{ kind: "registered", user }`를 반환하며 OAuth 라우트는 해당 사용자의 세션을 저장해 로그인 성공으로 처리한다. 같은 이메일이더라도 카카오 회원번호가 다르면 이 반환 경로를 사용하지 않고 `email_conflict` pending 생성·갱신과 관리자 확인을 유지한다.

## 회원 탈퇴 사용자 경험

회원은 `내 정보 → 설정 → 회원 탈퇴`에서 탈퇴를 시작한다.

1. 탈퇴 시 삭제·보존되는 항목을 안내한다.
2. 실수를 막기 위해 사용자가 `탈퇴`를 직접 입력한다.
3. 최종 버튼은 파괴적 동작임을 명확히 표시한다.
4. 처리 중에는 중복 요청을 막는다.
5. 성공하면 인증 상태를 비우고 홈으로 이동하며 완료 메시지를 표시한다.
6. 실패하면 계정이 삭제되지 않았음을 알리고 재시도를 안내한다.

관리자 계정도 동일한 본인 탈퇴 절차를 사용한다. 마지막 관리자 여부에 따른 별도 제한은 정식 운영 전 관리자 정책이 확정될 때 추가한다.

## 서버 API

### 엔드포인트

```text
DELETE /api/users/me
```

요청 대상은 항상 `req.session.userId`이며 body나 URL에서 사용자 ID를 받지 않는다. 비로그인 요청은 `401`을 반환한다. 요청 body에는 오작동 방지를 위한 확인 문자열만 허용한다.

```json
{
  "confirmation": "탈퇴"
}
```

확인 문자열이 다르면 `400`을 반환한다.

### 카카오 연결 해제

서버는 사용자의 저장된 `kakaoId`와 현재 환경의 서버 전용 어드민 키로 카카오 연결 해제 API를 호출한다.

- 개발: `KAKAO_DEV_ADMIN_KEY`
- 운영: `KAKAO_PROD_ADMIN_KEY`
- `REPLIT_DEPLOYMENT="1"`이면 운영 키, 그 외에는 개발 키 선택

어드민 키는 브라우저 응답, `VITE_` 환경변수, 로그, 저장소에 노출하지 않는다. 카카오 연결 해제가 일시적으로 실패하면 로컬 계정을 삭제하지 않고 재시도 가능한 오류를 반환한다. 이미 외부에서 연결이 해제된 상태임을 카카오가 명확히 응답하는 경우에는 로컬 삭제를 계속할 수 있도록 카카오 오류 코드를 분리해 처리한다.

OAuth 토큰 교환 응답의 액세스 토큰은 브라우저에 반환하지 않는다. 현재 로그인 처리에서 액세스 토큰을 별도 저장하지 않으며, 회원 탈퇴도 토큰 저장 없이 어드민 키 방식으로 처리한다.

### 로컬 데이터 처리

카카오 연결 해제 성공 후 하나의 DB 트랜잭션에서 다음 순서로 처리한다.

1. 동문 명부의 `matched_user_id`를 `NULL`, `is_matched`를 `false`로 변경
2. 미발행 `community_events` 초안 삭제
3. 게시글, 댓글, 발행 경조사, 기존 부고의 작성자 연결을 `NULL`로 변경
4. 결제 기록의 사용자 연결을 `NULL`로 변경
5. 같은 카카오 회원번호 또는 이메일의 가입대기 기록 삭제
6. 해당 사용자의 모든 서버 세션 삭제
7. `users` 행 삭제

트랜잭션이 실패하면 로컬 변경을 전부 롤백하고 오류를 반환한다. 카카오 연결 해제는 이미 완료됐을 수 있으므로 오류 메시지는 재로그인 대신 운영자 문의가 필요할 수 있음을 안내하고, 서버에는 개인정보가 아닌 오류 종류와 처리 단계만 기록한다.

현재 세션은 DB 처리 후 `req.session.destroy()`로 정리하고 `connect.sid` 쿠키를 삭제한다.

| 확인 문자열 불일치 | 400 | 변경 없음 |
| 어드민 키 누락 | 500 | 변경 없음 |
| 카카오 연결 해제 일시 실패 | 502 | 변경 없음 |
| 로컬 트랜잭션 실패 | 500 | 롤백 |
| 성공 | 200 | 개인정보 삭제 및 관계 익명화 |

카카오 API의 전체 응답, 키, 토큰, 사용자 개인정보는 로그에 남기지 않는다.

## 코드 구조

- `server/kakao-oauth-config.ts`: 승인된 OAuth 범위와 환경별 REST OAuth 설정
- `server/kakao-admin-config.ts`: 환경별 서버 전용 어드민 키 선택
- `server/kakao-login.ts`: 토큰 교환부터 회원 생성·세션용 결과까지 서버 소유 로그인 처리
- `server/client-user.ts`: 클라이언트 허용 회원정보 직렬화
- `server/alumni-match.ts`: PostgreSQL 명부의 정규화 전화번호·이름 매칭과 단일 연결
- `server/kakao-unlink.ts`: 카카오 연결 해제 요청과 안전한 오류 분류
- `server/storage.ts`: 트랜잭션 기반 회원 데이터 제거 메서드
- `server/routes.ts`: 본인 탈퇴 API와 세션 종료
- `shared/birthday.ts`: 양력·음력 생일의 한국 날짜 판정
- `client/src/pages/login.tsx`: 수집항목 안내
- `client/src/pages/profile.tsx`: 선택 프로필 사진 표시
- `client/src/components/profile/settings-dialog.tsx`: 회원 탈퇴 진입점과 확인 UI
- `client/src/pages/privacy.tsx`: 실제 처리 범위와 탈퇴 절차
- `client/src/pages/terms.tsx`: 실제 수집항목과 카카오 로그인 표현 정리

탈퇴 확인 UI는 설정 대화상자 안에 중첩 대화상자를 만들지 않는다. 설정을 닫고 별도의 `AlertDialog`를 열어 중첩 모달과 포커스 충돌을 피한다.

## 테스트 및 검증

### 자동화 테스트

- OAuth authorize URL에 이름·이메일·전화번호·프로필 사진·생일만 포함되고 CI가 없음
- 카카오 로그인 처리가 개인정보 왕복 없이 서버에서 완료되고 토큰·원본 오류가 응답에 없음
- 공통 회원 직렬화가 허용 목록 밖의 DB 필드를 응답에서 제외함
- 같은 카카오 회원번호·이메일·정규화 전화번호·동문 명부 행으로 중복 회원을 만들지 않음
- 실제 Development Database에서 관리자 승인과 OAuth pending refresh를 경쟁시켜 승인 회원 한 명, 새 pending 0건, refresh의 승인 회원 반환을 확인하고 `finally` 정리 후 관련 레코드 0건을 확인함
- 로그인 매칭 경로가 Google Sheets가 아닌 PostgreSQL `alumni_database`를 사용함
- 양력·음력·윤달 생일 판정과 본인 전용 축하 배너
- 환경별 어드민 키 선택과 누락 오류
- 비로그인 및 잘못된 확인 문자열 거부
- 카카오 연결 해제 실패 시 로컬 삭제 미호출
- 성공 시 세션 사용자만 삭제하고 쿠키 정리
- 저장소 탈퇴 처리의 관계 해제·초안 삭제·회원 삭제 순서
- 로그인·약관·개인정보 화면에 필수/선택 조건과 탈퇴 경로가 존재함
- 프로필 사진과 대체 표시가 모두 존재함

### Replit 개발 환경

```bash
npm test
npm run check
npm run build
```

개발 서버에서 다음을 확인한다.

- 공개 상태에서 `/login`, `/privacy`, `/terms` 접근
- 카카오 로그인 및 온보딩
- 프로필 사진 제공/미제공 표시
- 회원 탈퇴 경고와 확인 문자열 검증
- 개발 카카오 앱 연결 해제 및 개발 DB 데이터 처리
- 탈퇴 후 세션 401과 재가입 가능 여부

### 카카오 심사용 자료

실제 개발 또는 운영 화면을 사용하되 개인정보가 보이지 않도록 가상 데이터 또는 완전한 마스킹을 적용한 PDF 한 개를 만든다. PDF에는 다음 흐름을 순서대로 담는다.

1. 서비스명이 보이는 로그인 화면
2. 필수·선택 수집항목과 목적
3. 카카오 동의 화면
4. 가입 및 로그인 완료 화면
5. 내 정보의 회원 탈퇴 진입점
6. 탈퇴 안내와 확인 화면
7. 탈퇴 완료 후 홈 또는 로그인 화면
8. 개인정보 처리방침의 수집항목·목적·탈퇴 관련 부분

최종 카카오 신청은 PDF와 실제 운영 화면, 개인정보 처리방침의 내용이 동일한지 확인한 후 사용자 확인을 받아 제출한다.

## 완료 조건

- 카카오에서 실제 사용하는 이름·이메일·전화번호·프로필 사진·생일만 요청하고 CI는 요청하지 않는다.
- 로그인 화면과 개인정보 처리방침에 필수·선택 조건과 목적이 일치한다.
- 프로필 사진이 실제 서비스에서 사용된다.
- 생일이 본인 전용 생일 축하 MVP에서 실제 사용되고 선택 동의 철회 시 저장값이 제거된다.
- PostgreSQL 동문 명부와 기존 회원 식별자로 중복가입을 방지한다.
- 회원 탈퇴에 카카오 연결 해제와 로컬 개인정보 삭제가 포함된다.
- 자동화 테스트, 타입 검사, 빌드가 Replit 개발 환경에서 통과한다.
- 개인정보가 없는 심사용 PDF가 준비된다.
- 최종 신청 직전까지 카카오 콘솔 입력값이 준비되며, 제출은 사용자 확인 후 수행한다.
