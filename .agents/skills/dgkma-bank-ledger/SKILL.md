# 동문회 일반회계 통장 기장

기장·분개만 요청받으면 파일 첨부 여부와 관계없이 이 스킬로 시작한다. 기업은행 송금 후에도 같은 절차를 실행한다. 거래일시·금액·잔액은 은행 자료에서, 용도와 귀속연도는 회계장부와 증빙에서 확인한다. 조회나 미리보기만 요청하면 대조 결과를 제공한다.

## 대상 찾기

- 동문회 Google Drive 계정에서 **은행별 통장 원장**과 **일반계좌 거래내역**을 구별한다. 2026년 기준 [은행 원장](https://docs.google.com/spreadsheets/d/1d9C3cMd_0MomQtF5cfAk-9doVKRxsy8OKiO1MqvYqA0/edit)의 탭은 `기업은행(시작일~종료일)`·`토스뱅크(시작일~종료일)` 형식이고, [일반계좌 거래내역](https://docs.google.com/spreadsheets/d/1aStEZeCSHIUqS4W81umlW8B3pMCJpx-u5Oe_IHcD49k/edit)은 연도별 탭과 `회비수입` 탭이 있다. 다음 연도에는 거래일에 해당하는 원장과 연도 탭을 확인한다. 파일명 끝의 날짜만으로 조회 기준일을 판정하지 않는다.
- 연결된 Google Sheets 도구로 실제 문서·탭 ID, 헤더, 마지막 실거래, 하단 합계, 연도 탭의 결산 피봇·체크썸 위치를 확인한다. 업무별 분류·분개·검산 사례는 노션 **동문회 회계관리 → [일반회계 장부 작성 매뉴얼](https://app.notion.com/p/41e2225d9c4d8196a397de7ac2b60c4b)**에 있다. 행번호는 매번 다시 찾는다.

## 1. 마지막 검산 거래부터 현재까지 조회

1. 해당 계좌의 직전 검산 결과에서 **은행과 두 장부의 실거래를 빠짐없이 대조하고 잔액까지 맞춘 마지막 거래**를 찾는다. 일시·부호 있는 금액·잔액을 양쪽 장부에서 다시 확인한다. 더 최근에 입력된 개별 거래가 있어도 검산을 마친 거래부터 시작한다. 검산 근거가 없거나 기존 차이가 있으면 그 차이 이전의 검산 거래까지 거슬러 간다. 그런 거래도 없으면 확인된 기초잔액이나 계좌 개설 시점부터 대조한다.
2. 기준 거래를 포함해 **이번 은행 조회 기준시각(한국시간)까지 해당 계좌의 전체 입출금**을 대조한다. 같은 범위를 담은 송금 후 조회 결과나 사용자가 방금 받은 은행 파일은 재사용한다. 과거 자료는 경계 거래를 겹쳐 빠진 기간을 추가 조회한다.
   - 기업은행은 `ego-browser`로 로그인한 계좌의 ‘거래내역조회’에서 이름·금액·입출금 방향 필터를 해제해 전체를 조회한다. `메인컨텐츠프레임`에 `#grid_area-table`이 표시되면 `page.evaluate()` 한 번으로 거래일시부터 원장 B:M에 해당하는 12개 열과 조회 기준시각·합계를 함께 읽는다.
   - 화면의 입금·출금 합계와 마지막 잔액을 읽은 거래와 맞추고, 건수가 표시되면 함께 대조한다. 조회 범위와 원장에 필요한 열이 확인되면 그대로 기장한다. 필요한 값이 누락·마스킹됐거나 전체 파일 한 번이 더 간단하면 ‘엑셀파일저장(출력용)’을 이용한다.
   - 스크립트 안에서 거래행을 두 장부와 대조하고 기장에 필요한 값을 전달한다. 모델에는 건수·합계·검산 결과와 분류 또는 불일치 판단에 필요한 행만 출력한다.
3. 지목한 분개가 기준 거래보다 과거이면 해당 거래와 증빙도 별도로 대조한다. 현재까지의 증분은 그대로 수행한다. 로그인 인증이 필요하면 은행 화면을 사용자에게 넘긴다. 직접 조회하기 어려운 계좌는 최신 입출금 내역을 요청한다. 확인된 구간은 먼저 처리하고 남은 조회 기간을 보고한다.

## 2. 은행 거래와 두 장부 대조

1. 은행·계좌·조회기간, 실제 거래행, 날짜 체계와 정렬 방향, 출금·입금 열을 식별한다. 헤더가 없는 자료는 겹치는 실제 거래와 해당 은행 탭의 열 값을 대조해 형식을 확인한다. 계좌·자료 종류를 정할 수 없으면 대상만 물어본다.
2. **기업은행 XLSX.** Excel 서식 오류나 무헤더 파일은 스킬 폴더 기준 `python3 scripts/read_ibk_xlsx.py "입력.xlsx"`로 구조를 확인한다. `--rows`를 붙이면 셀값을 저장된 문자열 또는 null로 읽는다. 원래 행 순서와 빈 열 위치를 유지한다. 여러 시트면 `--sheet "시트명"`으로 고른다. 행 JSON은 로컬에서 파싱하고 화면에는 필요한 대조 결과만 출력한다. 실제 사용한 무헤더 파일의 A:L은 **거래일시, 출금, 입금, 거래후 잔액, 거래내용, 상대계좌번호, 상대은행, 메모, 거래구분, 수표어음금액, CMS코드, 상대계좌예금주명** 순이다. 원장 A는 누적 순번, 수신한 12개 필드는 B:M에 대응한다. 헤더 유무와 거래 정렬 방향은 내려받은 파일마다 다를 수 있다. 다른 양식과 토스 자료는 실제 헤더·기존 은행 탭을 기준으로 매핑한다. 판독 도구가 처리하지 못한 양식은 사용 가능한 스프레드시트 도구로 읽고 원본과 같은 기준으로 대조한다. 숫자 금액·잔액은 원 단위로, 계좌번호·메모는 텍스트로 취급한다.
3. **계좌 + 한국시간 초 단위 거래일시 + 부호 있는 금액(입금−출금) + 거래 후 잔액**으로 조회 구간 전체를 은행 원장 및 연도별 장부와 각각 대조한다. 실거래 건수에는 분개 원거래 한 건을 포함한다. 장부의 전기·차기이월과 분개 상세는 제외한다. 토스·기업 간 이전은 계좌별 실거래 두 건이다.
4. 복수 파일의 겹친 기간, 같은 초·금액의 거래는 계좌별 잔액 흐름·은행 순번·건수·원래 적요까지 비교한다. 일괄 `UNIQUE`로 없애지 않는다. 전각·반각이나 날짜 표시 차이는 비교할 때만 정규화한다. 원본 메모는 보존한다. 같은 키의 의미 있는 필드가 충돌하거나 중간 거래가 빠져 잔액이 이어지지 않으면 해당 구간과 차액을 보고한다. 연속성이 확인된 구간은 계속 처리한다.
5. 각 목적지에서 기존·누락·중복 또는 불일치 건수, 추가할 입출금 합계와 반영 후 잔액을 계산한다. 한쪽에만 있는 실거래는 빠진 쪽만 보완한다. 두 곳에 이미 있는 거래도 요청받은 분개·분류는 기존 행에 적용하고, 같은 구간의 다른 입출금까지 대조한다.

## 3. 은행 원장과 연도별 장부에 반영

- **은행 원장.** 시간순으로 해당 계좌의 거래 목록에 넣는다. 기업은행은 합계행 바로 위에 필요한 행만 삽입해 누적 순번을 잇고, 직전 일반 거래 서식을 적용한다. 과거 누락분이면 뒤에 붙이지 말고 시간순 위치와 후속 순번을 맞춘다. 거래목록 전체의 출금·입금 합계, 헤더의 현재잔액·조회기간, 탭명의 종료일을 확인한다. 기존 합계 수식은 보존하고 고정 숫자로 관리하는 값만 다시 계산한다. 부분기간 파일을 받았을 때는 누적 원장의 시작일·마지막 잔액·종료일을 과거로 되돌리지 않는다. 같은 종료일이면 탭 이름을 유지한다.
- **연도별 장부.** 거래일에 맞는 탭의 실제 입력 영역에만 쓴다. B 거래일시는 기존과 같은 날짜·시간 값(초), C 구분은 `수입`·`지출`, D는 부호 있는 원화 금액, E는 그 계좌의 거래 후 잔액, F는 확인된 납부자·수취인·가맹점, G는 거래구분, H는 용도 메모, I는 기존 계좌 표기(`기업`·`토스`)다. 과거 거래는 시간순 위치의 거래 영역에 넣고, 기존 분개 묶음의 중간을 가르지 않는다. 일반 행 서식·유효성 검사를 이어받고 옆의 결산표·피봇과 아래의 이월행·수식을 보존한다.
- **분류.** 은행 메모와 기존 사례를 우선한다. 입금자나 용도가 모호하면 관련 1:1 카카오톡과 기존 납부 내역·증빙을 먼저 확인한다. 예를 들어 조의금·축의금 지급은 C `지출`, G `경조사비`이고 H에는 기수·이름·경조사와 지급 목적을 쓴다. 같은 사람의 문자비, 화환비, 오입금 환불과 구분한다. 용도가 모호해도 확실한 은행 사실은 기장하고 미확정 분류는 행번호·실제 일시·금액·원문 적요와 함께 문의한다.
- **분개.** 대납·혼합입금 등 한 거래를 나누면 은행 원장에는 실거래 한 건을 둔다. 연도별 장부는 원거래 행의 C·G를 `분개`로 두고 E의 거래 후 잔액을 보존한다. 바로 아래에 용도별 상세를 두고 상세 E는 비운다. 이미 있는 원거래와 상세를 대조해 필요한 부분만 반영하고, 상세의 부호 있는 금액 합계가 원거래 금액과 일치하는지 확인한다.
- **회비·이전·취소.** 수입 회비는 해당 회계연도의 회원 표기를 사용하고 H에는 `YYYY년도 회비`만 쓴다. 별도 연도가 없으면 입금연도를 쓴다. `회비수입` 탭에는 기존 QUERY가 반영하므로 값을 복제하지 않는다. 통장이전 양쪽은 C·G `통장이전`, 확인된 카카오T 가승인·전액취소 쌍은 G `승인 후 전액취소`로 맞춰 결산에서 제외한다. 실제 운임과 그 환급은 `교통비`다. 상세 서식과 기준은 매뉴얼을 따른다.
- **재시도.** 각 목적지에 쓰기 직전에 마지막 거래·합계행·대상 셀이 대조한 상태인지 다시 읽는다. 변경됐으면 차집합과 행번호를 다시 구한다. 문서별 변경을 묶어 쓰고 결과를 재조회한다. 은행 원장 성공 후 장부 쓰기가 실패하거나 요청 결과가 불명확하면 두 곳을 다시 읽어 누락분만 이어서 처리한다.

## 4. 검산과 후속 정산

1. 두 장부를 다시 읽어 조회 구간 **전체 실거래**의 일시·금액·잔액·출현 횟수를 은행 자료와 각각 맞춘다. 신규 0건일 때도 같은 검사를 한다. 누락과 중복·초과가 각 장부에서 0건인지, 구간의 입금·출금 건수와 합계, 은행 원장 누적 합계, 마지막 계좌 잔액이 맞는지 확인한다. 계좌별로 기준 거래부터 직전 잔액 + 입금 − 출금 = 다음 잔액이 매번 성립해야 한다.
2. 결산 피벗의 수입·지출 건수와 부호 있는 합계를 장부에서 독립 집계한다. 분개는 상세를 결산에 포함한다. 장부·결산표·회비수입 탭의 조회 기준일을 검증한 조회기간과 맞춘다. 마지막 실거래가 피벗 범위 안에 있고, **체크썸(마감 잔액 − 전기이월금)과 피벗 총계의 차이가 0원**인지 확인한다. 2026년은 N1이 마지막 실거래 잔액에서 D4를 차감한다. 여러 일반계좌가 동시에 열려 있으면 같은 기준일의 계좌별 기말잔액 합계에서 기초잔액 합계를 빼 별도로 대조한다. 그 기간 거래가 없는 계좌도 포함하며, N1이 한 계좌 잔액만 사용해 생긴 차액과 구분한다. 차이가 있으면 조회 범위·누락 거래·분개·피벗 범위를 확인하고 근거가 있는 누락을 보완한 뒤 다시 검산한다.
3. 기존 노션 **동문회 회계관리**에 대응하는 미결·송금자 확인 건이 있으면, 대상자·경조사나 용도·금액·입출금 방향이 일치하고 해당 장부 행을 재조회한 뒤 처리한다. 여러 건에 대응할 수 있으면 해당 항목만 보류한다. 지급일·실제 금액·지급 경로·연도별 장부 행 링크를 남긴다. 같은 사람의 다른 경조사나 업체 지급을 구별하고 요약 건수·금액과 일치하는지 재조회한다. 이미 완료한 송금의 증빙만 보강한 경우 건수를 다시 더하지 않는다. 기장 요청의 범위는 은행 원장·장부와 관련 정산 기록까지다. 이체 실행, 공지 발송, 회비 명부나 홈페이지 DB 변경은 각각 해당 업무의 요청에 따른다.
4. 결과에 계좌명, 은행 조회 기준시각(KST), 양쪽 장부의 반영 행과 신규 입금·출금 건수 및 합계, 남은 누락·중복 건수, 마지막으로 검산한 실거래의 일시·부호 있는 금액·잔액, 체크썸·피벗 총계·차액을 적는다. 조회 구간 전체의 대조와 결산이 맞아야 검산 완료로 보고한다. 일부만 확인했으면 검산을 마친 거래와 남은 구간·차액을 명시해 다음 기장 때 이어간다. 용도가 미확정인 거래는 따로 표시한다. 개인 계좌번호나 불필요한 원문은 보고서·프로젝트 파일에 넣지 않는다.
